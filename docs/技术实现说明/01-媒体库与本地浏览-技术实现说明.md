## 1. 架构概览

媒体库与本地浏览模块横跨 **数据层**、**领域层** 和 **UI 层**，核心设计原则如下：

- **MediaStore 为真相源**：`App.kt` 源码注释明确拒绝 "从进程启动时递归扫描外部存储根目录"，所有媒体发现优先通过 Android `MediaStore` 完成，仅在必要时回退到文件系统遍历。
- **三层缓存体系**：内存缓存（`LruCache`）→ 磁盘缓存（应用私有目录）→ MediaStore/文件系统，层层降级。
- **视图与数据解耦**：同一套底层扫描数据通过不同的 Scanner（`FolderViewScanner`、`TreeViewScanner`、`VideoScanUtils`）支撑 Album View、Tree View、Media Library 三种上层视图。
- **协程 + Flow 驱动的响应式 UI**：扫描、缩略图生成、元数据提取均在 `Dispatchers.IO` 上执行，通过 `StateFlow`/`SharedFlow` 向 Compose UI 层推送状态变更。

## 3. 本地媒体浏览

### 3.1 MediaStore 扫描架构

#### 3.1.1 扫描策略

源码中存在 **三级扫描策略**，按优先级递减：

| 层级 | 实现 | 用途 | 性能特征 |
|------|------|------|---------|
| **L1: MediaStore** | `ContentResolver.query()` 查询 `MediaStore.Video.Media` / `MediaStore.Audio.Media` | 常规场景 | O(1) 索引查询，毫秒级 |
| **L2: 文件系统验证** | `folder.listFiles()` + `FileTypeUtils` | 手动刷新、外部设备、MediaStore 滞后时 | O(n) 目录遍历 |
| **L3: 元数据提取** | `VideoMetadataCacheRepository` + `MediaMetadataRetriever` | `.ts/.mts/.m2ts` 时长修复、文件系统 fallback | I/O 密集型，批量执行 |

### 3.2 视频文件浏览

#### 3.2.1 文件夹列表扫描（FolderViewScanner）

`FolderViewScanner` 专门服务于 **Album View**（相册视图），只返回"含有直接视频子文件的文件夹"，不做递归统计。

```kotlin
// app/gyrolet/mpvrx/utils/storage/FolderViewScanner.kt
object FolderViewScanner {
  @Volatile private var folderCache: FolderCache? = null
  private const val CACHE_TTL_MS = 5 * 60_000L  // 5 分钟缓存

  suspend fun getAllVideoFolders(context, options, forceFileSystemCheck): List<VideoFolder> {
    // 1. 检查内存缓存（5 分钟 TTL）
    // 2. 扫描 MediaStore 的视频/音频直接子文件，按父文件夹聚合
    // 3. 返回 VideoFolder 列表，按名称字母排序
  }
}
```

扫描流程：
1. 查询 `MediaStore.Video.Media.EXTERNAL_CONTENT_URI`，按 `DATA` 列的父路径分组聚合
2. 若 `options.includeAudio` 为 true，追加查询 `MediaStore.Audio.Media.EXTERNAL_CONTENT_URI`
3. 将聚合结果转换为 `VideoFolder`，计算每个文件夹的 `videoCount`、`totalSize`、`totalDuration`、`lastModified`

#### 3.2.2 文件夹内视频列表扫描（VideoScanUtils）

```kotlin
// app/gyrolet/mpvrx/utils/storage/VideoScanUtils.kt
suspend fun getVideosInFolder(
  context: Context,
  folderPath: String,
  options: MediaScanOptions = MediaScanOptions(),
  forceFileSystemCheck: Boolean = false,
): List<Video> = withContext(Dispatchers.IO) {
  // Step 1: MediaStore 快速查询
  scanVideosFromMediaStore(context, normalizedFolderPath, videosMap, noMediaPathFilter)
  if (options.includeAudio) {
    scanAudioFromMediaStore(context, normalizedFolderPath, videosMap, noMediaPathFilter, options)
  }

  // Step 2: 修复 MediaStore 时长不可靠的格式（.ts/.mts/.m2ts 返回 0 时长）
  val zeroTsKeys = videosMap.keys.filter { key ->
    val v = videosMap[key] ?: return@filter false
    v.duration <= 0L && v.path.substringAfterLast('.').lowercase() in MEDIASTORE_DURATION_UNRELIABLE
  }
  for (key in zeroTsKeys) {
    val meta = metadataCache.getOrExtractMetadata(file, v.uri, v.displayName)
    if (meta != null && meta.durationMs > 0L) {
      videosMap[key] = v.copy(duration = meta.durationMs, durationFormatted = formatDuration(meta.durationMs))
    }
  }

  // Step 3: 文件系统验证（仅当 forceFileSystemCheck 为 true 或满足启发式条件时）
  if (shouldRunFilesystemVideoCheck(forceFileSystemCheck, videosMap.size)) {
    scanVideosFromFileSystem(context, folder, videosMap, options, noMediaPathFilter)
  }

  videosMap.values.sortedBy { it.displayName.lowercase(Locale.getDefault()) }
}
```

**关键设计——`.ts` 时长修复**：MediaStore 对 `.ts`、`.mts`、`.m2ts` 格式的 duration 返回 0。`VideoScanUtils` 在扫描后专门检测这些格式，通过 `VideoMetadataCacheRepository`（底层使用 `MediaMetadataRetriever` 或 FFmpeg 提取）补正时长。

#### 3.2.3 MediaFileRepository（统一仓库入口）


#### 3.6.3 Smart 模式策略

```kotlin
// app/gyrolet/mpvrx/domain/thumbnail/ThumbnailRepository.kt
private suspend fun generateWithFastThumbnails(video, mode, dimension): Bitmap? {
  val durationSeconds = resolvedDuration.coerceAtLeast(0L) / 1000.0
  val requestedPosition = when (mode) {
    ThumbnailMode.FirstFrame, ThumbnailMode.EmbeddedThumbnail -> 0.0
    ThumbnailMode.FrameAtPosition -> durationSeconds * (browserPreferences.thumbnailFramePosition.get() / 100.0)
    ThumbnailMode.Smart -> durationSeconds * 0.33  // 默认 33%
  }

  // Smart 模式回退策略：33% → 10s → 20s → 30s
  val positions = when (mode) {
    ThumbnailMode.Smart -> listOf(requestedPosition, 10.0, 20.0, 30.0)
    else -> listOf(requestedPosition)
  }.map { it.coerceIn(0.0, lastSafePosition) }.distinct()

  // 依次尝试，返回第一个非空帧
  for (position in positions) {
    val bitmap = FastThumbnails.generateAsync(targetVideo.path, position, dimension, dimension)
    if (bitmap != null && !bitmap.isAllBlackOrSolid()) return bitmap
  }
}
```

#### 3.8.2 进度计算与展示

```kotlin
// app/gyrolet/mpvrx/ui/browser/videolist/VideoListViewModel.kt
internal fun buildVideoWithPlaybackInfo(
  video: Video,
  playbackState: PlaybackStateEntity?,
  currentTimeMillis: Long,
  newLabelDays: Int,
  watchedThreshold: Int,
): VideoWithPlaybackInfo {
  val durationSeconds = video.duration / 1000L
  val progressValue = if (playbackState != null && durationSeconds > 0L) {
    val watchedSeconds = durationSeconds - playbackState.timeRemaining.toLong()
    (watchedSeconds.toFloat() / durationSeconds.toFloat()).coerceIn(0f, 1f)
  } else null

  val isWatched = playbackState?.hasBeenWatched == true ||
    (watchedThreshold > 0 && progressValue != null && progressValue >= watchedThreshold / 100f)

  return VideoWithPlaybackInfo(
    video = video,
    progressPercentage = progressValue?.takeIf { it in 0.01f..0.99f },  // 0% 和 100% 不显示进度条
    isWatched = isWatched,
    ...
  )
}
```

**关键设计**：
- `progressPercentage` 仅在 `[0.01, 0.99]` 范围内显示，避免未开始（0%）和已看完（100%）的视频显示无意义的进度条
- `watchedThreshold` 默认 95%，用户可配置 1-100%

### 3.9 未播放标记（NEW 标签）

#### 3.9.1 两种 NEW 标签实现

项目中存在 **两套** NEW/未播放标记逻辑，服务于不同视图：

**方案 A：TreeViewScanner 级别（基于文件修改时间）**

```kotlin
// app/gyrolet/mpvrx/utils/storage/TreeViewScanner.kt
private data class NewBadgeConfig(
  val enabled: Boolean,
  val thresholdMillis: Long,       // 天数 × 24×60×60×1000
  val playedMediaTitles: Set<String>,  // 已播放过的媒体标题集合
)

private fun isVideoNew(
  displayName: String,
  dateModifiedSeconds: Long,
  currentTimeMs: Long,
  newBadgeConfig: NewBadgeConfig,
): Boolean {
  if (!newBadgeConfig.enabled) return false
  if (displayName in newBadgeConfig.playedMediaTitles) return false  // 已播放过的不标记
  val videoAgeMs = currentTimeMs - (dateModifiedSeconds * 1000L)
  return videoAgeMs <= newBadgeConfig.thresholdMillis  // 在阈值天数内算 NEW
}
```

**方案 B：VideoListViewModel 级别（基于播放状态 + 修改时间）**

```kotlin
// app/gyrolet/mpvrx/ui/browser/videolist/VideoListViewModel.kt

// isWithinNewLabelWindow = (currentTime - video.dateModified*1000) <= newLabelDays*24*60*60*1000
```

#### 3.9.2 区别

| 维度 | TreeViewScanner（树状视图） | VideoListViewModel（视频列表） |
|------|---------------------------|------------------------------|
| 判断依据 | 文件修改时间 + playedMediaTitles | 播放进度 + 文件修改时间 |
| "已播放"定义 | 存在于 PlaybackState 且 hasBeenWatched=true | 同左 |
| 阈值来源 | `appearancePreferences.unplayedOldVideoDays` | 同左 |
| 适用场景 | 文件夹层级的 NEW 计数徽章 | 单个视频卡片的 NEW 标签 |

## 6. 性能优化策略

### 6.1 三级缓存

| 缓存层级 | 实现 | TTL | 触发失效 |
|---------|------|-----|---------|
| 内存缓存 | `LruCache<String, Bitmap>`（`maxMemory/6`） | 进程生命周期 | 低内存时系统自动回收 |
| 磁盘缓存 | `context.filesDir/thumbnails/local/{hash}.jpg` | 持久 | 文件修改时 key 变化 |
| Scanner 缓存 | `FolderViewScanner.folderCache` / `TreeViewScanner.cachedTreeViewData` | 5min / 10sec | `MediaFileRepository.clearCache()` |

### 6.2 延迟初始化与预热

```kotlin

```

### 6.3 可见区域感知加载

`VideoListScreen` 使用 `snapshotFlow` 监听 `LazyListState`/`LazyGridState` 的可见项索引，仅在滚动停止后（`THUMBNAIL_SCROLL_SETTLE_MILLIS` 延迟）对可见窗口内的项启动缩略图生成。

### 6.4 协程取消传播

所有扫描循环中均嵌入 `currentCoroutineContext().ensureActive()`，确保用户在快速切换视图或退出屏幕时，后台扫描任务能被及时取消，避免资源浪费。
