# 远程文件浏览器图片浏览功能需求文档

## 1. 需求背景与目标

### 1.1 背景
当前应用已支持通过 WebDAV、SMB、FTP、SFTP 协议连接远程服务器，并浏览、播放视频文件。但远程服务器中存储的图片文件（如电影海报、剧照、个人相册、漫画等）目前被系统忽略，无法在应用内展示和查看。

### 1.2 目标
- 扩展远程文件浏览器的文件识别能力，使其能够识别远程服务器中的常见图片格式
- 在远程文件浏览器列表中同时展示文件夹、视频和图片三类内容
- 提供文件类型过滤选项，让用户自主控制是否展示图片
- 支持点击图片进入查看器，并能够左右滑动浏览同文件夹下的其他图片
- 保持现有视频浏览体验不变，老用户默认习惯不受影响

## 2. 功能范围

### 2.1 In Scope（范围内）
- 仅针对远程服务器（WebDAV / SMB / FTP / SFTP）中的图片文件浏览与查看
- 图片文件在网络浏览器列表中的展示与过滤
- 图片缩略图加载与缓存
- 全屏图片查看器（支持左右滑动、双击放大、Pinch 缩放、旋转）
- 文件类型过滤选项（视频 / 图片）

### 2.2 Out of Scope（范围外）
- 本地文件系统中的图片浏览（本次不涉及本地存储图片的展示）
- 图片编辑功能（裁剪、滤镜、标注等）
- 图片上传/下载到远程服务器
- GIF 动画播放（列表和查看器中均展示静态首帧）
- 与视频的自动关联展示（如海报自动匹配到视频卡片）

## 3. 用户场景

### 场景一：浏览电影文件夹查看海报
用户在 NAS 上有一个电影文件夹，每个电影子文件夹中除了视频文件外，还有 `poster.jpg`、`fanart.jpg` 等海报图片。用户进入该文件夹后，勾选「图片」选项，即可在列表中看到视频和海报图片，点击海报可以放大查看。

### 场景二：浏览远程相册
用户在 WebDAV 服务器上有一个「旅行照片/2024-日本/」文件夹，内含 50 张 JPG 照片。用户进入文件夹后勾选「图片」查看照片缩略图网格，点击任意一张照片进入查看器，左右滑动浏览全部照片，双击放大查看细节。

### 场景三：默认习惯不受影响
老用户进入远程文件夹时，由于「图片」选项默认未勾选，界面与之前完全一致，只展示文件夹和视频，不会因新功能而感到困惑。

## 4. 功能详细设计

### 4.1 文件类型识别

#### 支持的图片格式
| 格式 | 扩展名 | MIME 类型前缀 |
|------|--------|---------------|
| JPEG | jpg, jpeg | image/jpeg |
| PNG | png | image/png |
| WebP | webp | image/webp |
| GIF | gif | image/gif |
| BMP | bmp | image/bmp |
| HEIC/HEIF | heic, heif | image/heic, image/heif |
| AVIF | avif | image/avif |

#### 识别规则
- 优先通过服务器返回的 `mimeType` 字段判断（以 `image/` 开头）
- 若 `mimeType` 为空，通过文件扩展名后缀匹配上述支持列表
- 不支持的格式（如 TIFF、RAW 相机原始格式）保持忽略，不识别为图片

### 4.2 网络浏览器列表展示规则

#### 默认状态
用户点击进入远程文件夹后，列表保持现有体验：**只展示文件夹和视频**。图片文件虽然被识别，但默认隐藏。

#### 展示图片后的列表结构
当用户在「排序与视图选项」中勾选「图片」后，列表分为三个区块依次展示：
1. **文件夹区块** — 与现有行为完全一致
2. **视频区块** — 与现有行为完全一致
3. **图片区块** — 新增，展示当前文件夹内所有图片文件

#### 排序行为
- 现有的排序方式（标题、日期、大小）对三类文件同时生效
- 同类型文件内部按当前排序规则排列
- 类型之间的先后顺序固定：文件夹 → 视频 → 图片

#### 搜索行为
- 搜索框输入关键字时，同步过滤图片文件名
- 搜索结果包含文件夹、视频、图片三类匹配项

### 4.3 排序与视图选项弹窗变更

在网络浏览器的右上角排序按钮弹窗中，**新增「文件类型（Media Types）」分组**：

- **分组标题**：Media Types / 文件类型
- **选项内容**：
  - 图片（Images）— 默认 ⬜ 未勾选
- **位置**：放在现有「显示选项」（Visibility Toggles）区域的上方或紧邻区域，视觉风格保持一致
- **交互逻辑**：
  - 勾选「图片」时，列表中新增展示图片区块（文件夹和视频保持原有显示）
  - 取消勾选「图片」时，隐藏图片区块（恢复为仅展示文件夹和视频）
  - 视频文件始终显示，不参与过滤切换

### 4.4 图片卡片设计

图片卡片**保持与现有视频卡片一致的视觉样式**：

- **列表模式**：左侧缩略图区域（16:9 比例），右侧展示文件名、文件大小、修改日期
  - 缩略图加载成功时，展示图片采样缩略图
  - 缩略图未加载时，展示图片图标占位（区别于视频的播放按钮图标）
- **网格模式**：卡片整体保持 16:10 比例，缩略图铺满卡片区域
  - 右下角可叠加格式角标（如 JPG、PNG）
  - 下方展示文件名（与视频网格卡片一致）

### 4.5 图片查看器设计

#### 进入方式
点击图片卡片 → 进入全屏图片查看器（新页面，全屏沉浸模式）。

#### 核心功能
| 功能 | 交互方式 | 说明 |
|------|----------|------|
| 左右滑动切换 | 横向滑动手势 | 按当前排序顺序浏览同文件夹下所有图片，循环不循环均可 |
| 双击放大/还原 | 双击屏幕 | 首次双击放大至适应屏幕或原始比例，再次双击还原 |
| 双指捏合缩放 | Pinch 手势 | 自由缩放图片，最小不低于适应屏幕比例 |
| 旋转 | 旋转按钮 / 手势 | 将图片顺时针旋转 90 度，解决手机拍摄照片方向问题 |
| 返回 | 系统返回手势 / 按钮 | 退出查看器，回到文件列表 |

#### 滑动浏览范围
- 仅浏览当前文件夹内、且在当前过滤条件下可见的图片
- 例如：用户通过搜索筛选后点击图片，滑动范围限定在搜索结果中的图片

#### 预加载策略
- 进入查看器加载当前图片时，后台预加载前一张和后一张图片
- 采用虚拟化机制：大量图片时只保留当前页及相邻页的 Bitmap，避免内存溢出

## 5. 技术实现方案

### 5.1 方案选择：独立图片缓存层（Dedicated Image Cache）

采用**独立图片缓存层**方案，不复用视频流的 NetworkStreamingProxy 代理架构。

#### 选择理由
1. **职责分离**：图片加载不依赖为视频播放设计的代理架构，避免 token 生命周期污染
2. **性能更优**：直接下载完整文件，无 NanoHTTPD 中间层跳转，每张缩略图少一次 HTTP 请求开销
3. **缓存可控**：可为缩略图和大图设置不同的缓存策略和尺寸限制
4. **已有工程决策**：项目中已记录「远程图片缓存策略：独立缓存层优于代理复用方案」的工程决策

### 5.2 核心组件

#### NetworkImageRepository（新增）
- **职责**：负责通过网络客户端下载远程图片文件到本地私有缓存目录，同时服务缩略图和大图两个场景
- **主要方法**：
  - `loadImage(connectionId, path)`：管理下载、缓存、错误状态
  - `getThumbnail(connectionId, path, maxSize)`：返回适合列表展示的缩略图 Bitmap
  - `getFullImage(connectionId, path)`：返回适合查看器展示的大图 Bitmap
- **核心设计**：
  - **下载一次，双重用途**：同一张图片的原图只需下载一次，先写入大图磁盘缓存，缩略图通过采样解码生成后写入缩略图磁盘缓存
  - 并发控制：同一张图片的重复请求自动合并（inFlight 机制）

#### 图片加载流程
```
1. UI 请求缩略图
2. 检查缩略图磁盘缓存 → 命中则直接返回
3. 未命中则检查大图原图磁盘缓存 → 命中则采样生成缩略图，存入缩略图缓存后返回
4. 均未命中则通过 NetworkClient.getFileStream() 下载远程原图
5. 原图存入大图磁盘缓存
6. 采样解码生成缩略图，存入缩略图磁盘缓存
7. 返回缩略图 Bitmap 给 UI

--- 查看器大图加载流程 ---
1. UI 请求大图
2. 检查大图磁盘缓存 → 命中则加载到内存并返回
3. 未命中则检查下载任务 → 如有正在下载的原图则等待
4. 均无则通过 NetworkClient.getFileStream() 下载远程原图
5. 存入大图磁盘缓存和查看器内存缓存
6. 返回大图 Bitmap 给 UI
```

#### ImageViewerScreen（新增）
- **职责**：全屏图片查看器页面
- **实现要点**：
  - 使用 HorizontalPager（Compose Foundation Pager）实现左右滑动浏览
  - 手势集成：双击放大、Pinch 缩放（Modifier.zoomable 或自定义）、旋转（graphicsLayer rotationZ）
  - ViewModel 生命周期管理：页面退出时取消未完成的下载任务

### 5.3 与现有组件的关系

| 现有组件 | 关系说明 |
|----------|----------|
| RemoteImageLoader | 共存但不耦合。RemoteImageLoader 继续负责 Jellyfin/Navidrome 等 HTTP 图片加载；NetworkImageRepository 负责远程协议（WebDAV/SMB/FTP）图片加载。两者缓存目录分离。 |
| NetworkBrowserScreen | 扩展：新增图片区块渲染逻辑，复用现有的列表/网格布局框架。 |
| NetworkBrowserViewModel | 扩展：新增图片文件识别逻辑（isNetworkImageFile），文件加载流程不变。 |
| ThumbnailRepository | 图片缩略图磁盘缓存接入现有 ThumbnailRepository 的磁盘目录体系（`filesDir/thumbnails/network/`），清理策略与视频缩略图保持一致。图片缩略图的生成逻辑由 NetworkImageRepository 处理（采样解码原图），不通过视频帧提取。 |
| NetworkStreamingProxy | 不使用。图片加载绕过代理层，直接通过网络客户端下载。 |

## 6. 缓存策略

### 6.1 缩略图缓存
- **尺寸**：列表模式约 128px~256px 长边，网格模式按屏幕密度动态计算
- **内存缓存**：LRU，按应用可用内存的 1/32 分配
- **磁盘缓存**：接入现有 ThumbnailRepository 磁盘目录体系 `filesDir/thumbnails/network/`，以 SHA-256 哈希作为文件名，JPEG 压缩存储
- **清理策略**：与视频缩略图保持一致 —— **无限增长 + 手动清理**（通过设置页面的「清除缓存」触发）。缩略图体积小，长期保留不影响存储空间
- **失效机制**：当远程文件被修改（lastModified 变化）或替换时，缓存自动失效并重新加载
- **生成方式**：下载原图后通过 `BitmapFactory` 采样解码（`inSampleSize`）生成，不重复下载

### 6.2 大图原图缓存
- **尺寸**：展示原图分辨率，不做人为压缩。加载时先解码至屏幕适配尺寸展示，后台继续解码完整分辨率，用户放大时可查看原图细节。对于极端大尺寸图片（如超过 8192px 长边），做上限保护以避免 OOM
- **磁盘缓存**：独立目录 `cacheDir/network_images/`，以 SHA-256 哈希作为文件名，按原图格式存储
- **清理策略**：采用**容量 + 时间双策略管理**：
  - 容量上限：如最大 500MB，超出时按 LRU 淘汰旧缓存
  - 时间清理：超过 30 天未被访问的缓存文件自动清理
  - 应用启动时异步执行一次过期扫描
- **按需加载**：用户未点击查看的图片不预加载原图；点击后加载当前张，同时预加载左右相邻两张

### 6.3 查看器内存缓存
- **生命周期**：查看器页面存活期间，所有已加载的原图 Bitmap 保留在内存中，左右滑动返回时直接命中，无需重新加载
- **释放时机**：查看器页面退出后，内存中的大图 Bitmap 优先释放，不长期驻留内存
- **占位策略**：滑动到尚未加载完成的图片时，先展示该图片的缩略图作为占位，大图加载完成后平滑替换

### 6.4 缓存清理
- 应用升级或缓存目录异常时，自动清理损坏或无法解码的缓存文件
- 缩略图缓存跟随视频缩略图一起被「清除缓存」功能清理
- 大图原图缓存不提供单独的用户手动清理入口（由系统自动按容量/时间策略管理）

## 7. 边界情况与异常处理

### 7.1 过滤与空状态

| 场景 | 预期行为 |
|------|----------|
| 勾选图片但当前文件夹无图片 | 列表展示文件夹 + 视频。若当前文件夹无图片，不显示图片区块 |
| 取消勾选图片 | 列表只展示文件夹 + 视频，图片区块隐藏 |
| 搜索状态下无图片匹配 | 搜索结果为空时，显示搜索空状态 |

### 7.2 图片查看器边界情况

| 场景 | 预期行为 |
|------|----------|
| 单张图片文件夹 | 进入查看器后左右滑动无效（只有一张），不显示滑动指示器 |
| 大量图片文件夹（500+ 张） | 查看器采用虚拟化机制，只保留当前页及相邻页的 Bitmap，避免内存溢出 |
| 图片加载失败 | 显示错误占位图，允许用户重试，不影响滑动到其他图片 |
| 网络断开 | 查看器内已缓存的图片可正常浏览；未缓存的图片显示断网提示，返回列表时同样提示连接不可用 |
| 大图已被清理、只剩缩略图 | 用户点击该图片查看时，先展示缩略图作为占位，同时后台重新下载原图；下载完成后平滑过渡为高清原图。若下载失败（断网或服务器不可用），提示「点击重试」|
| 滑动到边界 | 到达第一张或最后一张时，提供视觉边界反馈（如轻微回弹或提示文字） |

### 7.3 格式与兼容性

| 场景 | 预期行为 |
|------|----------|
| GIF 动图 | 列表和查看器中均展示静态首帧，暂不支持动画播放 |
| 不支持的格式（TIFF、RAW 等） | 不识别为图片，保持忽略状态 |
| 图片文件损坏 | 解码失败时显示错误占位图，不崩溃 |
| 图片尺寸极大（如 100MP） | 查看器加载时做上限保护（如超过 8192px 长边则采样加载），避免 OOM；缩略图仍按目标尺寸采样 |

### 7.4 安全与隐私

- 图片缓存存储在应用私有目录，不进入系统相册，不暴露给用户或其他应用
- 网络客户端访问远程图片时，复用已有的连接认证信息，不额外请求权限
- 图片查看器不记录浏览历史或截图

## 8. 非功能需求

### 8.1 性能要求
- 缩略图加载：列表滚动时，图片缩略图应在 300ms 内完成首次展示（命中缓存时立即展示）
- 查看器滑动：相邻图片预加载完成后，左右滑动切换应达到 60fps，无明显卡顿
- 内存占用：浏览包含 1000 张图片的文件夹时，内存增长不超过 50MB（依赖虚拟化和采样机制）

### 8.2 兼容性要求
- 最低支持 Android API 与现有应用保持一致
- 支持 WebDAV、SMB、FTP、SFTP 四种远程协议的图片加载
- 图片查看器手势在 TV 模式下（遥控器/手柄操作）可降级为按钮切换

### 8.3 用户体验要求
- 老用户升级应用后，默认体验与之前完全一致（图片默认隐藏）
- 文件类型过滤选项的状态应持久化保存，下次进入网络浏览器时恢复用户上次的设置
- 图片加载过程中展示轻量级占位动画，避免白块
