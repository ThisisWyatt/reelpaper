# 13. 持久化播放列表 — 技术实现说明

> 本文档基于 mpvRx 项目源码（截至数据库 schema v25）进行逐层分析。所有内容均直接来源于代码，未经验证的信息不做推测。

---

## 一、模块概述

持久化播放列表（Persistent Playlist）是 mpvRx 中用于长期保存用户创建的媒体列表的子系统。它与“播放队列（Playback Queue）”明确区分：

- **持久化播放列表**：长期存储在 Room 数据库中，支持创建、编辑、导入 M3U/Xtream Codes 等，对应首页 Playlists Tab。
- **播放队列**：当前播放的临时媒体序列，由 `PlaybackSession` 管理，生命周期与播放器绑定。

本模块的核心职责包括：

1. 本地播放列表的 CRUD（创建、读取、更新、删除）
2. 播放列表项的顺序管理与重排
3. M3U/M3U8 网络/本地播放列表的导入与刷新
4. Xtream Codes IPTV 账户的导入与流解析
5. 收藏夹（Favorites）作为特殊受保护播放列表
6. 播放历史（lastPlayedAt、playCount、lastPosition）的持久化
7. 与播放器（PlayerActivity）的集成，支持整列表续播

- `clearPlayHistoryForFile(filePath)` — 清除指定文件的历史记录
- `markFileLastPlayed(filePath, timestamp)` — 标记最后播放时间
- `clearResumePositionForFile(filePath)` — 清除恢复位置
- `getRecentlyPlayedInPlaylist(playlistId, limit): List<PlaylistItemEntity>` — 获取最近播放项

#### 分类与收藏（M3U IPTV 支持）
- `observeDistinctCategories(playlistId): Flow<List<String>>` — 观察所有 distinct groupTitle

- `remotePlaylistWriteMutex`：保护 M3U/Xtream 远程播放列表的导入与刷新，防止并发更新同一远程源。

#### 3.1.2 收藏夹（Favorites）特殊处理

```kotlin

```

收藏夹是一个受保护的特殊播放列表：
- `getOrCreateFavoritesPlaylist(isAudio)`：按需创建/获取，名称匹配不区分大小写

#### 3.1.3 路径规范化与匹配

```kotlin
private fun normalizePlaylistPath(filePath: String): String =
  if (filePath.startsWith("file://", ignoreCase = true)) Uri.parse(filePath).path ?: filePath else filePath

private fun playlistPathKey(filePath: String): String {
  val cleanPath = normalizePlaylistPath(filePath)
  val uri = runCatching { Uri.parse(cleanPath) }.getOrNull() ?: return cleanPath
  return if (uri.scheme.isNullOrBlank()) cleanPath else uri.normalizeScheme().toString()
}

private fun isPathMatching(pathA: String, pathB: String): Boolean =
  pathA.isNotBlank() && pathB.isNotBlank() && playlistPathKey(pathA) == playlistPathKey(pathB)
```

- 自动去除 `file://` 前缀
- URI scheme 标准化后比较，确保同一文件的不同表示形式被识别为重复

#### 3.1.4 音频/视频分类

```kotlin
private suspend fun classifyAndFilterPlaylists(
  playlists: List<PlaylistEntity>,
  targetIsAudio: Boolean,
): List<PlaylistEntity>
```

- M3U/IPTV 列表可能混合音频和视频，保留在其导入的分类中（`isM3uPlaylist` 为 true 时按原分类处理）
- 对于非 M3U 列表，若 `isAudio` 为 false 但包含音频文件，则自动更新 `isAudio = true`

#### 3.1.5 M3U 播放列表操作

**创建 M3U 播放列表（从 URL）**：
```kotlin
suspend fun createM3UPlaylist(url: String, userAgent: String? = null): Result<Long>
```
流程：
1. 调用 `loadRemotePlaylist()` 加载远程内容
2. 若 URL 疑似 YouTube/网络播放列表且需要 yt-dlp，优先尝试 `YtdlpManager.extractPlaylist()`
3. 回退到 `M3UParser.parseFromUrl()` 解析标准 M3U
4. 调用 `persistM3UPlaylist()` 持久化

**从文件/内容创建**：
- `createM3UPlaylistFromFile(context, uri)` — 从本地文件导入
- `createM3UPlaylistFromContent(content, sourceName, sourceUrl, userAgent)` — 从文本内容导入
- `createM3UPlaylistFromParsed(parseResult, sourceName, sourceUrl, userAgent)` — 从已解析结果直接持久化

**刷新 M3U 播放列表**：
```kotlin
suspend fun refreshM3UPlaylist(playlistId: Int): Result<Unit>
```
- Xtream 播放列表走 `refreshXtreamPlaylist()`
- 普通 M3U 重新下载源内容，调用 `replaceRemotePlaylist()` 事务性替换

**持久化逻辑**（`persistM3UPlaylist`）：
1. 若 `sourceUrl` 非空，查找已有相同源 URL 的播放列表
2. 若存在，调用 `replaceRemotePlaylist()` 更新
3. 若不存在，新建 `PlaylistEntity`（`isM3uPlaylist = true`）并批量插入所有项

**替换逻辑**（`replaceRemotePlaylist`）：
1. 获取旧项，按 `normalizeLocalMediaReference(filePath)` 建立映射
2. 按 `tvgId` 建立备用映射
3. 对 Xtream 项，按 `xtreamItemIdentity()` 建立映射
4. 新项匹配旧项时，保留 `addedAt`、`lastPlayedAt`、`playCount`、`lastPosition`、`isFavorite`
5. 事务性替换：清空旧项 → 批量插入新项 → 更新列表元数据

#### 3.1.6 Xtream Codes 支持

```kotlin
suspend fun createXtreamPlaylist(serverUrl: String, username: String, password: String): Result<Long>
```

流程：
1. `xtreamClient.loadCatalog(serverUrl, username, password)` 获取节目单
2. 密码通过 `credentialCipher.encrypt()` 加密存储
3. 若账户已存在（通过 `xtreamServerUrl` + `xtreamUsername` 查找），更新现有列表
4. 若不存在，创建新列表，名称为 `Xtream – <host>`
5. 调用 `secureXtreamPlaylist()` 处理所有流 URL：
   - 将原始 Xtream URL 转换为内部 `XtreamPlaybackUri` 格式（隐藏真实凭证）
   - 从标题/元数据中擦除密码（替换为 `•••`）
   - 对 URL 中的密码进行安全处理

```kotlin
suspend fun resolveXtreamStream(reference: XtreamPlaybackUri.Reference): Result<String>
```

用于播放器请求时实时解析 Xtream 流的真实 URL（通过 `XtreamStreamingProxy` 代理）。

#### 3.1.7 窗口化加载（大列表优化）

```kotlin
suspend fun getPlaylistItemsWindowAsUris(
  playlistId: Int,
  centerIndex: Int = 0,
  windowSize: Int = 100,
): List<Uri>
```

- 总数 ≤ `windowSize` 时直接返回全部
- 总数 > `windowSize` 时，以 `centerIndex` 为中心计算窗口范围
- 通过 `getPlaylistItemsInRange()` 只加载可见范围内的项

## 四、M3U 解析器

**源码位置**：`app/src/main/java/app/gyrolet/mpvrx/utils/media/M3UParser.kt`

`M3UParser` 是一个单例对象（`object`），提供有资源限制的 M3U/M3U8 解析能力。

### 4.1 资源限制

```kotlin
data class M3ULimits(
  val maxBytes: Long = 32L * 1024 * 1024,   // 32 MB
  val maxLines: Int = 300_000,
  val maxEntries: Int = 100_000,
)
```

所有入口函数均受上述限制保护，防止恶意/超大播放列表导致内存耗尽。

### 4.2 支持的 M3U 扩展

- `#EXTM3U` — 播放列表头部
- `#EXTINF:<duration>,<title>` — 条目信息，支持属性：`tvg-id`、`tvg-name`、`tvg-logo`、`group-title`
- `#KODIPROP:inputstream.adaptive.license_type` / `license_key` — Kodi DRM 属性
- `#EXTVLCOPT:http-user-agent` — VLC 选项（User-Agent）
- HLS 媒体清单检测：`#EXT-X-` 开头时返回特定错误，提示直接播放

### 4.3 入口函数

- `parseFromUrl(url, userAgent, headers, httpClient, limits)` — 从 HTTP/HTTPS URL 加载并解析
- `parseFromUri(context, uri)` — 从本地 Content URI 解析
- `parseFromStream(inputStream, sourceUrl, overridePlaylistName, limits)` — 从输入流解析
- `parseContent(content, sourceUrl, overridePlaylistName, limits)` — 从字符串解析

### 4.4 URL 处理

- `sanitizeSourceUrl(sourceUrl)` — 去除 URL 中的 `user:password@` 凭证信息后再持久化
- `normalizeLocalMediaReference(reference)` — 将 `file://` URI 和编码路径统一为解码后的文件系统路径
- `resolveMediaUrl(sourceUrl, entry)` — 解析相对路径为绝对 URL，支持 HTTP(S) 和文件系统相对路径

### 4.5 安全设计

- URL 凭证剥离：解析前从 URL 中移除 `username:password`，使用 `Credentials.basic()` 单独设置 Authorization 头
- `LimitedInputStream`：限制读取字节数，超出时抛出 `M3ULimitException`
- 取消支持：协程取消时会关闭底层流，中断阻塞的网络读取

```kotlin
  // 1. 本地列表先更新（即时反馈）

  val item = currentItems.removeAt(fromIndex)
  currentItems.add(toIndex, item)
  _videoItems.value = currentItems
  
  // 2. 持久化新顺序到数据库

  playlistRepository.reorderPlaylistItems(playlistId, newOrder)
}
```

## 七、Xtream 流代理

**源码位置**：`app/src/main/java/app/gyrolet/mpvrx/data/network/proxy/XtreamStreamingProxy.kt`

`XtreamStreamingProxy` 是一个本地 NanoHTTPD 代理服务器（`127.0.0.1:0`，随机端口），用于：

1. **隐藏真实凭证**：播放器只访问本地代理 URL（含随机 token），代理内部通过 `PlaylistRepository.resolveXtreamStream()` 获取真实流地址
2. **HLS 支持**：检测到 `.m3u8` 时重定向到 `HlsStreamingProxy`
3. **Range 请求透传**：支持断点续传/拖动进度

**注册流**：

返回本地代理 URL，如 `http://127.0.0.1:<port>/xtream/<token>/stream.ts`

**解析流**：

## 九、关键设计决策

### 9.1 为什么使用 position 而非链表结构

`PlaylistItemEntity` 使用整数 `position` 字段表示顺序，而非链表（next/prev 指针）。原因：
- Room + SQLite 对整数索引查询效率极高
- 重排时只需更新受影响项的 position（`reorderPlaylistItems` 事务逐条更新）
- 分页查询（`getPlaylistItemsWindow`、`getPlaylistItemsInRange`）可直接用 SQL `LIMIT/OFFSET` 或范围条件

### 9.2 为什么 M3U 和本地列表共用同一套表结构

`PlaylistEntity` / `PlaylistItemEntity` 同时承载本地文件列表和 M3U IPTV 列表：
- 减少数据库表数量，简化迁移
- M3U 专用字段（`tvgId`、`groupTitle` 等）对本地列表只是留空
- 通过 `isM3uPlaylist` / `isXtreamPlaylist` 布尔字段区分行为

代价：本地列表的 Entity 包含较多 M3U 专用字段，存在一定冗余。

### 9.3 写操作的 Mutex 设计

- `playlistWriteMutex` 是协程级 `Mutex`，非线程级 `synchronized`
- 所有修改 position 或批量写入的操作都通过 `withLock` 保护
- `remotePlaylistWriteMutex` 单独保护远程源，避免本地操作阻塞网络刷新

### 9.4 文件存在性检查策略

`PlaylistViewModel.getActualVideoCount()` 和 `PlaylistDetailViewModel` 都会检查本地文件是否存在：
- 通过 `MediaFileRepository.getVideosForBuckets()` 批量扫描父目录（利用缓存）
- 未匹配到的文件回退到单文件查询或生成合成 `Video`
- M3U 列表跳过文件系统检查（URL 无法预先验证）

### 9.5 收藏状态持久化策略

M3U 列表刷新时，收藏状态通过以下机制保留：
1. `replaceRemotePlaylist()` 获取旧项的 `isFavorite`
2. 新项按 `normalizeLocalMediaReference(filePath)` 匹配旧项
3. 匹配成功时继承旧项的 `isFavorite`、`lastPlayedAt`、`playCount`、`lastPosition`
4. `PlaylistDao.getFavoriteFilePaths()` 用于外部备份收藏状态
