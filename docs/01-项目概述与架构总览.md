## 1. 项目定位

mpvRx 是一款基于 **libmpv** 的 Android 多媒体播放器，采用 **AGPL-3.0-or-later** 许可证开源。其核心特征为：

- 以 mpv（通过 `mpvlib` AAR）作为底层解码与渲染引擎，通过 JNI 与 Kotlin 层交互
- UI 层完全基于 **Jetpack Compose** 构建
- 支持本地文件、网络协议（SMB/FTP/WebDAV）、流媒体（HLS/torrent/yt-dlp）、Jellyfin/Navidrome 媒体服务器等多种播放源
- 集成 AI 字幕翻译、在线字幕搜索、HDR 着色器管线（Anime4K / hdr-toys）、音频可视化器等高级功能

## 5. 核心架构设计

### 5.1 播放状态机：PlaybackSession

`PlaybackSession` 是一个 **Kotlin `object` 单例**，实现 `MPVLib.EventObserver`，是应用内对 libmpv 原生核心的唯一进程级持有者。

**设计要点（来自 `PlaybackSession.kt` 源码注释与实现）：**
- Android 的 Activity/Service 均不拥有原生播放核心，只观察或控制 `PlaybackSession`
- 屏幕旋转、PiP、后台播放、通知重新进入等场景，通过 **Surface 绑定/解绑** 实现，而非销毁/重建原生核心
- 视频解码在 Android 无渲染表面时会被主动挂起，但轨道 ID 保持进程级存储，避免 Activity 重建丢失
- 提供 `StateFlow<PlaybackSessionState>` 与 `StateFlow<PlaybackQueueState>` 供 UI 观察
- 通过 `PlaybackProperty<T>` 泛型封装对 mpv 属性的观察，属性在核心未就绪时仍可安全访问

**状态关键字段：**
```kotlin
data class PlaybackSessionState(
  val phase: PlaybackPhase,           // UNINITIALIZED / INITIALIZING / IDLE / LOADING / READY / BACKGROUND / STOPPING / ERROR
  val generation: Long,               // 会话代际，用于区分不同加载周期
  val activeGeneration: Long,
  val surfaceAttached: Boolean,
  val paused: Boolean,
  val currentItem: PlaybackItem?,
  val error: String?,
)
```

### 5.2 导航架构

- 路由基接口 `Screen`，所有屏幕实现该接口并提供 `@Composable Content()`
- 使用 **Navigation3**（`androidx.navigation3`）而非传统的 Navigation Compose
- `MainActivity` 通过 `rememberSaveableBackStack(initial = HomeScreen)` 管理返回栈，使用 `CompositionLocalProvider(LocalBackStack)` 向下传递

### 5.3 主题系统

- 内置 **32 套**预设主题（`AppTheme` 枚举），涵盖 Default、Dynamic(Material You)、Catppuccin、Nord、Tokyo Night、Rose Pine、Gruvbox、Dracula 等
- 每套主题均提供 **Light / Dark / AMOLED 纯黑** 三种配色方案
- 支持 **动态取色**（Android 12+）与 **用户自定义主题**（`CustomThemeDefinition` 序列化存储）
- 主题切换采用 **Telegram 风格径向揭示动画**（`ThemeTransitionState`）：捕获当前屏幕 Bitmap → 以点击位置为中心径向遮罩揭示新主题
- 使用 `MaterialExpressiveTheme` + `MotionScheme.expressive()` 实现 Material 3 Expressive 动效

## 6. 数据库架构

`MpvRxDatabase`（Room）当前版本 **21**，包含 **12 个实体**：

| 实体 | 对应 DAO | 核心用途 |
|------|---------|---------|
| `PlaybackStateEntity` | `PlaybackStateDao` | 播放位置、速度、音轨/字幕选择、外部字幕路径 |
| `RecentlyPlayedEntity` | `RecentlyPlayedDao` | 最近播放历史（含视频标题、时长、尺寸、播放列表关联） |
| `VideoMetadataEntity` | `VideoMetadataDao` | 视频元数据缓存（分辨率、帧率、时长、编码信息） |
| `NetworkConnectionEntity` | `NetworkConnectionDao` | SMB/FTP/WebDAV 网络连接配置 |
| `PlaylistEntity` | `PlaylistDao` | 播放列表（支持 M3U、Xtream、音频标记） |
| `PlaylistItemEntity` | `PlaylistDao` | 播放列表项（含 TVG ID、Logo、DRM 许可信息、收藏标记） |
| `DirectoryScanEntity` | `DirectoryScanDao` | 目录扫描索引（指纹、视频数、总时长、大小） |
| `SecureMediaEntity` | `SecureMediaDao` | 安全文件夹加密媒体 |
| `NetworkStreamEntryEntity` | `NetworkStreamEntryDao` | 网络流条目（torrent/直链/YouTube，含海报/TMDB 元数据） |
| `JellyfinServerEntity` | `JellyfinServerDao` | Jellyfin 服务器连接信息 |
| `DownloadItemEntity` | `DownloadItemDao` | 下载任务队列（含 Jellyfin 关联、进度、状态） |
| `NavidromeServerEntity` | `NavidromeServerDao` | Navidrome 服务器连接信息 |

**迁移策略：**
- `DatabaseModule.kt` 中定义了 **20+ 条 Migration**（`MIGRATION_1_2` 至 `MIGRATION_20_21` 及 `MIGRATION_19_21`）
- 部分迁移为**修复型迁移**（如 `MIGRATION_8_9` 修复了 secondarySubDelay/externalSubtitles 的 schema 错位问题）
- 使用 `WRITE_AHEAD_LOGGING` 日志模式

## 7. 关键设计决策（可从代码直接推断）

| 决策 | 证据 | 影响 |
|------|------|------|
| **进程级播放核心** | `PlaybackSession` 为 `object` 单例，注释明确说明 "none of them owns the native core" | 旋转/PiP/后台不中断播放，Surface 变化与核心生命周期解耦 |
| **热感知性能降级** | `ThermalMonitor` 存在，PlaybackSession 中 ambient shader 预算与 Anime4K 质量受 thermal headroom 影响 | 高温时自动降低 GPU 负载 |
| **Deferred 初始化** | `App.kt` 中 `scheduleFastThumbnailWarmupOnce()` 与 `scheduleMetadataMaintenanceOnce()` 故意延迟到首次 Activity 启动后 | 避免冷启动时与首帧竞争资源 |
| **Activity 生命周期回调** | `App` 实现 `Application.ActivityLifecycleCallbacks`，对 `PlayerActivity` 做大量性能埋点（`PlaybackPerformanceTrace`） | 精确测量播放器启动、暂停、销毁各阶段耗时 |
| **MediaStore 为真相源** | `App.kt` 注释明确拒绝 "从进程启动时递归扫描外部存储根目录" | 避免大媒体库下的存储唤醒与重复工作 |
| **网络凭证加密** | `NetworkCredentialCipher` 使用 `AndroidNetworkCredentialKey`（基于 Android Keystore） | 用户保存的 SMB/FTP 密码经硬件级密钥加密 |
