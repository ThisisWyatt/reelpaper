# 帧捕获与收藏功能需求与设计文档

> 文档状态：待评审  
> 关联需求：播放视频时捕获帧图像并在应用内集中管理，支持查看详情及跳转回视频播放。

---

## 1. 需求概述

### 1.1 背景

mpvRx 已具备成熟的截图能力（通过 mpv 的 `screenshot-to-file` 命令保存到系统相册 `Pictures/mpvSnaps`），但帧捕获保存后即脱离应用管理，用户无法在应用内回顾、整理或基于帧捕获快速定位回原视频场景。

### 1.2 目标

在播放器现有的「逐帧导航」面板中增加「保存到帧捕获与收藏」功能，用户可在逐帧导航时精确选择目标帧，一键保存到应用内的「帧捕获与收藏」进行管理。用户可在底部导航栏的「帧捕获」标签页中集中浏览所有帧捕获，像查看普通图片一样查看大图细节，并可选择跳转回对应视频的时间点继续播放。

### 1.3 用户价值

- 快速收藏视频中的精彩瞬间，无需离开应用去系统相册翻找
- 帧捕获与视频时间点强关联，一键跳转回看上下文
- 在应用内形成个人视频高光时刻的集中库

## 3. 非功能需求

| 编号 | 需求描述 |
|------|---------|
| NFR-01 | **性能**：帧捕获与收藏页加载 1000 张帧捕获时，首屏渲染时间不超过 500ms；滚动帧率保持 60fps |
| NFR-02 | **存储**：应用内仅保存帧捕获元数据（路径、视频信息、时间点），不存储任何图片文件，不生成缩略图副本，不压缩原图。系统相册中仅保留一份原始帧质量的文件 |
| NFR-03 | **兼容性**：数据库迁移从版本 28 到 29，需无损新增表，不影响现有数据 |
| NFR-04 | **可访问性**：所有按钮和帧捕获项支持 TalkBack 朗读；图片查看页支持双击放大/缩小 |
| NFR-05 | **一致性**：新增 UI 遵循 mpvRx 现有的 Material3 主题、动画风格、字体层级和间距规范 |

## 4. 界面与交互设计

### 4.1 逐帧导航面板 — 保存到收藏按钮

- **位置**：在「逐帧导航」Sheet 的底部按钮行中，在现有「截图」按钮旁边增加「保存到帧捕获与收藏」按钮
- **按钮样式**：与现有截图按钮保持一致的圆形按钮样式，使用不同的图标以区分功能（如相册/收藏相关图标）
- **点击行为**：触发双轨保存——以原始帧质量（无损、不压缩、不生成额外副本）保存到系统相册，成功后自动将帧捕获元数据（图片路径、视频路径、标题、时间点）写入应用数据库，数据库中不存储任何图片文件
- **加载状态**：保存过程中按钮显示加载指示，完成后恢复并弹出 Toast
- **共享设置**：与现有截图按钮共享「截图中包含字幕」开关状态

### 4.2 底部导航栏 — 帧捕获标签

- **标签页**：在底部导航栏新增「帧捕获」标签页
- **偏好控制**：标签的显示/隐藏由「外观设置」控制，默认显示
- **标签属性**：
  - 图标：使用相册/收藏相关的 Material 图标
  - 标签文字：「帧捕获」
  - 激活宽度：参考现有标签规范（约 100~108 dp）
- **页面内容**：由独立的帧捕获页面承载，注册到导航系统中

### 4.3 帧捕获与收藏页 — 网格浏览

- **布局**：使用网格布局或列表布局，本地文件夹内类的浏览功能类似，支持视图与排序设置
- **缩略图加载**：加载系统相册中的帧捕获文件，支持占位图和错误图状态。缩略图尺寸控制在 256×256 以内，避免内存压
- **排序**：默认按捕获时间倒序（最新在前）
- **空状态**：居中大图标 + 标题 + 说明文字

### 4.4 帧捕获详情页 — 大图查看器

- **入场动画**：从缩略图位置展开到全屏
- **图片展示**：支持双指缩放，复用项目已有的图片查看基础设施
- **左右滑动**：支持左右滑动切换相邻帧捕获
- **顶部信息栏**：半透明背景，显示视频标题、时间点、帧捕获日期
- **底部操作栏**：
  - 左侧：「跳转至视频」按钮（主操作，使用高亮样式）
  - 右侧：「删除」图标按钮
- **系统栏处理**：进入详情页时隐藏系统状态栏和导航栏，退出时恢复

## 5. 导航与路由

### 5.1 底部导航集成

- 底部导航栏新增「帧捕获」标签页
- 标签的显示/隐藏由「外观设置」控制
- 标签宽度和样式遵循现有底部导航规范
- 点击标签后进入帧捕获与收藏页面

### 5.2 帧捕获详情页导航

- 帧捕获与收藏页面内部维护独立的页面栈
- 点击帧捕获项时进入详情页，详情页接收帧捕获 ID 参数
- 从详情页跳转视频时：关闭详情页，打开视频播放器并传入视频路径和时间点

## 6. 错误处理与边界情况

| 场景 | 处理策略 |
|------|---------|
| 帧捕获时视频正在缓冲/无帧可截 | 提示「当前无法帧捕获，请等待视频加载」 |
| 帧捕获保存到系统相册成功，但数据库写入失败 | 提示用户帧捕获已保存到相册，但应用内记录失败，可稍后手动刷新 |
| 原视频文件被删除或移动 | 跳转视频前检查文件存在性，不存在则 Snackbar 提示「原视频已无法访问」 |
| 原视频为网络视频且当前断连 | 遵循「网络视频可用性懒检测原则」，点击跳转时才验证连接，断连则提示并提供移除选项 |
| 帧捕获文件在系统相册中被用户手动删除 | 应用内帧捕获与收藏展示时检测到文件不存在，显示占位图，点击后提示「帧捕获文件已删除，是否移除记录？」 |
| 数据库中帧捕获记录过多（>5000） | 分页加载，避免一次性加载导致内存压力 |

| **导航 / 页面栈** | 帧捕获与收藏页和详情页均使用现有的页面导航机制 |
