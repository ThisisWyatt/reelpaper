## 10.1 主题系统

### 10.1.1 架构概览

主题系统的核心由三部分组成：

1. **主题定义层**：`AppTheme` 枚举定义所有内置预设主题的颜色常量
2. **自定义主题层**：`CustomThemeDefinition` 数据类支持用户自定义主题
3. **主题应用层**：`MpvrxTheme` Composable 函数将主题应用到整个应用，并管理 Material You 动态取色、深色模式、AMOLED 模式等逻辑

核心文件：
- `app/src/main/java/app/gyrolet/mpvrx/ui/theme/AppTheme.kt`
- `app/src/main/java/app/gyrolet/mpvrx/ui/theme/Theme.kt`
- `app/src/main/java/app/gyrolet/mpvrx/preferences/AppearancePreferences.kt`

### 10.1.2 内置预设主题实现

源码中 `AppTheme` 枚举（`AppTheme.kt` 第 169~536 行）定义了 **32 套内置预设主题**（含 `Default` 和 `Dynamic`）。每套主题包含以下颜色属性：

| 属性 | 说明 |
|------|------|
| `titleRes` | 主题名称的字符串资源 ID |
| `primaryLight` / `primaryDark` | 亮色/暗色主题主色 |
| `secondaryLight` / `secondaryDark` | 亮色/暗色主题次色 |
| `tertiaryLight` / `tertiaryDark` | 亮色/暗色主题第三色 |
| `backgroundLight` / `backgroundDark` | 亮色/暗色主题背景色 |
| `isDynamic` | 是否为动态主题（仅 `Dynamic` 为 `true`） |

主题列表情形（源码中完整定义的主题）：Default、Dynamic、Catppuccin、Aurora、Cloudflare、CottonCandy、Doom、GreenApple、Gruvbox、Kanagawa、Lavender、Midnight、Mocha、Strawberry、Tidal、Nord、RosePine、TakoGreen、TokyoNight、YinYang、Yotsuba、Sapphire、Sunset、Ocean、Forest、RoseGold、Violet、Amber、Coral、Slate、Dracula、Monochrome。

**亮色配色方案生成逻辑**（`getLightColorScheme()`，第 541~605 行）：

1. 计算派生色：
   - `primaryContainer` = `primaryLight` 以 0.22 alpha 叠加在 `backgroundLight` 上
   - `secondaryContainer` = `secondaryLight` 以 0.22 alpha 叠加
   - `tertiaryContainer` = `tertiaryLight` 以 0.22 alpha 叠加
   - `surfaceVariant` = `primaryLight` 以 0.10 alpha 叠加在 `backgroundLight.darken(0.035f)` 上
   - `surfaceDim` = `backgroundLight.darken(0.075f)`
   - `surfaceBright` = `backgroundLight.lighten(0.012f)`
   - `surfaceContainerLowest` ~ `surfaceContainerHighest` 通过不同 alpha 值的主色叠加背景色生成

2. **对比度安全处理**：主色、次色、第三色都会经过 `withMinimumContrastAgainst()` 方法处理，确保在各类背景表面上的对比度不低于 **4.5:1**（WCAG AA 标准）。该方法使用二分查找（12 次迭代）调整颜色，必要时向黑/白混合。

3. 最终通过 `lightColorScheme()` 构建完整的 Material 3 `ColorScheme`。

**暗色配色方案生成逻辑**（`getDarkColorScheme()`，第 610~666 行）类似，但 Container 色使用 `darken(0.2f)` 而非 alpha 叠加，surfaceVariant 固定在 `#2A2A2A` 基础上叠加。

**AMOLED 纯黑模式**（`getAmoledColorScheme()`，第 692~704 行）：
- 基于暗色方案，将 `background`、`surface`、`surfaceDim`、`surfaceContainerLowest` 替换为纯黑 `Color.Black`
- `surfaceContainer` 设为 `#0A0A0A`，`surfaceContainerLow` 设为 `#050505`
- 其他 surface 层级通过主色以极低 alpha（0.05~0.08）叠加在 `#151515` / `#1F1F1F` 上，保持微弱层次感

### 10.1.3 Material You 动态取色

动态主题仅在 Android 12+（`Build.VERSION_CODES.S`）生效。`resolveAppColorScheme()` 函数（`Theme.kt` 第 344~376 行）处理动态取色逻辑：

```kotlin
appTheme.isDynamic && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
  when {
    useDarkTheme && amoledMode -> dynamicDarkColorScheme(context).copy(...pure black surfaces...)
    useDarkTheme -> dynamicDarkColorScheme(context)
    else -> dynamicLightColorScheme(context).withComfortableLightSurfaces()
  }
}
```

- 使用 Compose Material3 官方 API：`dynamicDarkColorScheme(context)` / `dynamicLightColorScheme(context)`
- 亮色动态主题会经过 `withComfortableLightSurfaces()` 处理（第 379~397 行），将纯白背景替换为低彩度薰衣草灰基调（`#F7F5F8`），再以主色微量染色（0.018~0.098 不同层级），避免纯白画布的刺眼感

### 10.1.4 深色模式实现

`DarkMode` 枚举（`Theme.kt` 第 399~405 行）定义三种模式：

```kotlin
enum class DarkMode(@StringRes val titleRes: Int) {
  Dark(R.string.pref_appearance_darkmode_dark),
```

`MpvrxTheme` 中（第 291~296 行）根据设置值决定实际使用的主题：

```kotlin
val useDarkTheme = when (darkMode) {
  DarkMode.Dark -> true
  DarkMode.Light -> false
  DarkMode.System -> darkTheme  // 跟随系统 isSystemInDarkTheme()
}
```

### 10.1.5 自定义主题编辑器

**数据模型**：`CustomThemeDefinition`（`AppTheme.kt` 第 24~161 行）

- 包含 9 个颜色字段：name、primaryLight/Dark、secondaryLight/Dark、tertiaryLight/Dark、backgroundLight/Dark
- 序列化格式：`|name|primaryLight|primaryDark|secondaryLight|secondaryDark|tertiaryLight|tertiaryDark|backgroundLight|backgroundDark`
- 兼容旧版 5 字段格式（缺少 secondary/tertiary 时默认使用 primary 色）
- 集合序列化：使用 Base64(URL_SAFE + NO_WRAP) 编码每个主题字符串，以逗号分隔

**持久化存储**：
- 自定义主题列表存储在 PreferenceStore 的 `"custom_theme"` 键中
- 当前选中的自定义主题名存储在 `"selected_custom_theme_name"` 键中
- 初始化时（`AppearancePreferences.kt` 第 116~120 行）会自动迁移旧版单主题数据到新的命名体系

**编辑界面**：`CustomThemeEditorScreen`（`CustomThemeEditorScreen.kt`）

- 提供实时预览：顶部显示亮色/暗色两种预览卡片
- 可编辑的 9 个颜色字段，每个字段包含颜色圆形预览 + HEX 输入框
- 验证逻辑：空名称、重复名称、无效 HEX 格式都会阻止保存
- 编辑模式切换：`CustomThemeEditorMode.Light` / `CustomThemeEditorMode.Dark`

### 10.1.6 主题切换动画（Telegram 风格径向揭示）

实现位于 `Theme.kt` 第 70~249 行。

**核心类 `ThemeTransitionState`**：
- `isAnimating`: 动画是否进行中
- `clickPosition`: 用户点击触发切换的位置（用于径向中心）
- `screenshotBitmap`: 切换前截取当前界面的位图
- `animationProgress`: 0f → 1f 的动画进度

**动画流程**：
1. 用户点击主题切换按钮 → `startTransition(position)` 被调用
2. 捕获当前 View 的位图：`view.drawToBitmap()`
3. 新主题在下方完成一帧重组（`withFrameNanos { }`）
4. 旧界面截图覆盖在最上层，通过径向渐变蒙版（radialGradient）实现揭示效果
5. 蒙版中心在点击位置，半径从 0 扩展到屏幕四角最大距离 + 30dp 羽化边
6. 动画时长 650ms，缓动曲线 `FastOutSlowInEasing`
7. 位图延迟 96ms 后回收，避免 Compose 尚未释放 ImageBitmap

**蒙版细节**（第 220~238 行）：
- 使用 `BlendMode.DstIn` 混合模式
- 渐变 stops：`0f→Transparent` → `clearStop→Transparent` → `softStop→Black@0.28` → `1f→Black`
- 创造出柔软的模糊边缘效果，而非生硬切割

**无障碍支持**：若系统开启减少动画（`reduceMotion`），动画直接 snap 到 1f，无过渡效果。

### 10.1.7 字体系统

`MpvrxTheme`（第 335 行）根据偏好选择字体：

```kotlin
typography = if (useSystemFont || localeNeedsSystemFont) SystemTypography else AppTypography
```

- `useSystemFont` 来自用户偏好 `"use_system_font"`
- `localeNeedsSystemFont` 通过 `localeRequiresSystemFont(configuration.locales[0])` 判断某些 locale 必须使用系统字体

## 10.2 壁纸与背景

### 10.2.1 架构概览

壁纸系统由三层组成：
1. **壁纸宿主**：`AppWallpaperHost` — 在根布局层级提供壁纸背景
2. **壁纸渲染**：`WallpaperImage` — 处理缩放、偏移、模糊、透明度
3. **壁纸编辑器**：`WallpaperEditorScreen` — 提供可视化编辑界面

核心文件：
- `app/src/main/java/app/gyrolet/mpvrx/ui/theme/AppWallpaper.kt`
- `app/src/main/java/app/gyrolet/mpvrx/ui/preferences/WallpaperEditorScreen.kt`

### 10.2.2 壁纸宿主实现

`AppWallpaperHost`（`AppWallpaper.kt` 第 52~116 行）：

```kotlin
@Composable
fun AppWallpaperHost(content: @Composable () -> Unit) {
  // 从偏好读取壁纸配置
  val wallpaperUri by preferences.customWallpaperUri.collectAsState()
  val wallpaperZoom by preferences.customWallpaperZoom.collectAsState()
  // ... offsetX, offsetY, scaleMode, blur, alpha
  
  // 异步加载位图（IO 线程）
  val wallpaper = produceState<Bitmap?>(initialValue = null, wallpaperUri) {
    val loaded = withContext(Dispatchers.IO) { loadWallpaperBitmap(context, wallpaperUri) }
    value = loaded
  }.value
}
```

**布局结构**（从内到外）：
1. 底层：`MaterialTheme.colorScheme.background` 纯色背景
2. 壁纸层：`WallpaperImage` 渲染用户选择的图片
3. 遮罩层：根据当前主题亮度自动叠加黑色 18% 或白色 30% 遮罩，确保文字可读性
4. 内容层：通过 `CompositionLocalProvider(LocalAppWallpaperActive provides wallpaperActive)` 向下传递壁纸激活状态

**壁纸感知背景色**：`wallpaperAwareBackgroundColor()`（第 119~120 行）在壁纸激活时返回 `Color.Transparent`，让下层壁纸可见；否则返回 `MaterialTheme.colorScheme.background`。

### 10.2.3 壁纸渲染引擎

`WallpaperImage`（第 122~168 行）处理所有视觉变换：

**缩放模式**：`WallpaperScaleMode` 枚举定义两种模式：
- `Fit`：图片完整显示（`ContentScale.Fit`），背景额外渲染一层放大 1.12x + 28dp 模糊 + 0.72 alpha 的填充层，避免留白
- `Fill`：图片裁剪填充（`ContentScale.Crop`）

**变换参数约束**：
- `zoom`: 1f ~ 3f（通过 `graphicsLayer.scaleX/Y`）
- `offsetX` / `offsetY`: -1f ~ 1f，映射为 `size.width/height * 0.35f` 的像素偏移
- `blurRadius`: 0f ~ 40dp（`MAX_WALLPAPER_BLUR_DP`）
- `imageAlpha`: 0f ~ 1f

### 10.2.4 壁纸位图加载与持久化

`loadWallpaperBitmap()`（第 197~219 行）：
- 支持 file:// URI 和 ContentResolver 流两种来源
- 先读取尺寸边界（`inJustDecodeBounds = true`）
- 若最大边超过 2560px，自动按 2 的幂次缩小（`inSampleSize`）
- 防止超大图片导致 OOM

`saveWallpaperCopy()`（第 172~195 行）：
- 将源图片复制到应用私有目录 `context.filesDir/wallpapers/`
- 使用临时文件命名 `wallpaper_XXXXX.image`
- 若源文件已在目标目录，直接返回原 URI

### 10.2.5 壁纸编辑器实现

`WallpaperEditorScreen`（`WallpaperEditorScreen.kt`）提供完整的可视化编辑：

**手势操作**（第 201~209 行）：
```kotlin
.pointerInput(sourceUri) {
  detectTransformGestures { _, pan, gestureZoom, _ ->
    zoom = (zoom * gestureZoom).coerceIn(1f, 3f)
    offsetX = (offsetX + pan.x / (size.width * 0.35f)).coerceIn(-1f, 1f)
    offsetY = (offsetY + pan.y / (size.height * 0.35f)).coerceIn(-1f, 1f)
  }
}
```
- 双指捏合缩放
- 单指拖动调整位置

**调节项**：
- 缩放模式切换：`Fit` / `Fill`（SegmentedButton）
- Zoom：1f ~ 3f（Slider）
- 水平/垂直位置：-1f ~ 1f（Slider）
- 模糊度：0f ~ 40f（Slider）
- 透明度：0f ~ 1f（Slider）
- 重置按钮：一键恢复所有参数到默认值

**保存逻辑**：调用 `saveWallpaperCopy()` 将图片复制到私有目录，再将所有参数写入 PreferenceStore。

- **`forceDarkPlayerButtonsBackground`**：强制使用深色按钮背景
- **`portraitPlaybackControlsPosition`**：竖屏播放控制按钮位置（`Center` 或 `BelowSeekbar`）
- **`playerTimeToDisappear`**：控制栏自动隐藏时间，默认 4000ms，支持 500~5000ms 预设值或自定义 100~1000000000000ms

## 10.4 动画与过渡

### 10.4.1 架构概览

动画系统分为三类：
1. **播放器控制动画**：控制栏出现/消失的动画风格
2. **视频打开动画**：视频开始播放时的入场效果
3. **导航/页面切换动画**：屏幕间和标签页间的过渡效果

核心文件：
- `app/src/main/java/app/gyrolet/mpvrx/ui/player/AnimationStyles.kt`
- `app/src/main/java/app/gyrolet/mpvrx/ui/utils/ScreenNavigation.kt`
- `app/src/main/java/app/gyrolet/mpvrx/ui/utils/NavigationPager.kt`

### 10.4.2 播放器控制动画

`ControlsAnimationStyle` 枚举（`AnimationStyles.kt` 第 49~58 行）定义 6 种风格：

| 风格 | 进入效果 | 退出效果 |
|------|---------|---------|
| Default | 水平滑入 + 淡入 | 水平滑出 + 淡出 |
| Cinematic Scale | 从 0.94x 缩放 + 淡入 | 缩放到 0.94x + 淡出 |
| Fluid Expand | 从 0.88x 缩放（低弹性）+ 淡入 | 缩放到 0.88x + 淡出 |
| Gentle Bounce | 水平弹性滑入 | 水平弹性滑出 |
| Minimal Fade | 纯淡入 | 纯淡出 |
| None | 无动画 | 无动画 |

**实现机制**：
- `buildControlsEnterH()` / `buildControlsExitH()`：水平方向控制（左右两侧按钮）
- `buildControlsEnterV()` / `buildControlsExitV()`：垂直方向控制（顶部/底部栏）
- 动画时长：`enterMs = (100 * animSpeed).coerceAtLeast(30)`，`exitMs = (300 * animSpeed).coerceAtLeast(50)`
- 弹簧动画参数来自 `AppMotion.Spatial.Expressive` / `Standard` / `Snappy` 预定义配置
- `reduceMotion` 偏好开启时，所有滑动动画降级为纯淡入淡出

**透明遮罩动画**（`PlayerControls.kt` 第 552~561 行）：
```kotlin
val transparentOverlay by animateFloatAsState(
  if (controlsShown && !areControlsLocked) .8f else 0f,
  animationSpec = if (controlsShown && !areControlsLocked) {
    playerControlsEnterAnimationSpec((100 * animSpeed).toInt().coerceAtLeast(30))
  } else {
    playerControlsExitAnimationSpec((300 * animSpeed).toInt().coerceAtLeast(50))
  },

```

### 10.4.3 视频打开动画

`VideoOpenAnimation` 枚举（`AnimationStyles.kt` 第 61~70 行）定义 6 种风格：

| 风格 | 效果 |
|------|------|
| Default | 无特殊效果（直接播放） |
| Fade from Black | 从黑屏淡出 |
| Zoom Burst | 黑屏缩放到 1.18x 并淡出 |
| Slide Up | 黑屏向上滑出并淡出 |
| Cinema Bars | 上下黑色遮罩条收缩消失 |
| None | 无动画 |

**实现**：`VideoOpenAnimationOverlay()`（第 347~464 行）

- `CinemaBars` 使用 `animateDpAsState` 将上下遮罩条从 110dp 动画到 0dp

### 10.4.4 导航/页面切换动画

**屏幕导航动画**：`NavigationAnimStyle` 枚举（`AnimationStyles.kt` 第 79~87 行）

| 风格 | 效果 |
|------|------|
| Default | 水平滑动（前进滑入，后退滑出带视差） |
| Depth Zoom | 深度缩放（前进：滑入+淡入；退出：缩小+淡出） |
| Fade through | 交叉淡化 + 轻微缩放 |
| Crossfade | 纯交叉淡化 |
| None | 无动画 |

实现位于 `ScreenNavigation.kt`（第 84~127 行）：
- 使用 Jetpack Navigation3 的 `NavDisplay`
- 过渡时长：`navigationDurationMillis(speed, baseMillis = 300)`，速度乘数 0.25x ~ 2.5x
- 预测性返回（Predictive Back）支持：根据滑动边缘（左/右）调整方向

**标签页导航动画**：`NavigationPager.kt`（第 89~111 行）

- 若动画风格为 `None` 直接调用 `scrollToPage()`，否则使用 `animateScrollToPage()` + `tween`

### 10.4.5 动画速度调节

`animationSpeed` 偏好（`PlayerPreferences` 中定义）是一个全局乘数：
- 范围：0.25f ~ 2.5f
- 影响所有动画时长：控制动画、导航动画、标签页切换
- 显示标签：`<0.6` 非常快 / `<0.9` 快 / `<1.1` 正常 / `<1.4` 慢 / 其他 非常慢

## 10.5 导航栏与布局

### 10.5.1 架构概览

### 10.5.3 导航栏状态管理

`NavigationBarState`（`NavigationBarState.kt`）是一个 Compose 状态对象，集中管理以下状态：

| 状态 | 类型 | 说明 |
|------|------|------|
| `isInSelectionMode` | `Boolean` | 是否处于多选模式 |
| `isDualPaneFolderSelected` | `Boolean` | 双栏布局中是否已选择文件夹 |
| `isMiniPlayerVisible` | `Boolean` | MiniPlayer 是否可见 |
| `isNavBarVisible` | `Boolean` | 导航栏是否在屏幕上 |
| `navbarLeftOffset` | `Dp` | 导航栏左侧偏移 |
| `navbarWidth` | `Dp` | 导航栏宽度 |
| `shouldHideNavigationBar` | `Boolean` | 是否应隐藏导航栏 |
| `navLabelVisibility` | `Float` | 标签文字可见度（1f=显示文字，0f=仅图标） |

**选择模式协调**（第 80~90 行）：
- 进入选择模式时，导航栏被隐藏（`isNavBarVisible = false`）
- 选择操作条替代导航栏显示
- `selectionOwner` 机制确保只有当前持有选择权的组件可以释放选择状态

**滚动自适应标签**（第 101~135 行）：
- `navScrollConnection` 是一个 `NestedScrollConnection`
- 用户向上滚动（内容向下）超过 60px 阈值 → `navLabelVisibility = 0f`（标签文字收起，仅显示图标）
- 用户向下滚动超过 60px 阈值 → `navLabelVisibility = 1f`（标签文字展开）
- 滚动方向反转时重置累计值，避免小幅反弹误触发

### 10.5.4 胶囊导航栏实现

`ExpressivePillNavigationBar`（`MainScreen.kt` 第 616~749 行）是一个自定义浮动导航栏：

**视觉设计**：
- `Surface` 形状为 `CircleShape`（胶囊形）
- 背景色：`surfaceContainerHigh`
- 阴影：`shadowElevation = 8.dp`，`tonalElevation = 6.dp`
- 边框：`outlineVariant@0.25 alpha`

**活跃指示器**：
- 一个 `primaryContainer` 颜色的圆角矩形在后台平滑移动
- 宽度和位置根据当前/目标标签页进行 `lerp` 插值
- 每个标签有固定活跃宽度（HOME/MUSIC 92dp，RECENTS 104dp，PLAYLISTS 108dp 等），非活跃时 44dp

**标签动画**：
- 文字透明度根据活跃分数 `activeFraction` 插值
- 图标与文字间距同样插值：`lerp(0.dp, 6.dp, activeFraction)`
- 颜色从 `onSurfaceVariant` 过渡到 `onPrimaryContainer`

**位置自适应**（第 573~607 行）：
- 默认居中（`centerFraction = 0.5f`）
- 双栏模式选中 HOME 时偏左（`0.2f`）
- 横屏/平板且 MiniPlayer 可见时靠左（`0f`）
- 位置变化通过 `animateFloatAsState` + `tween` 动画

### 10.5.5 导航栏隐藏与安全区域

**自动隐藏场景**：
1. 全屏播放时（通过 `shouldHideNavigationBar` 控制）
2. 多选模式时（选择操作条替代导航栏）
3. 权限被拒绝时（`isPermissionDenied`）

**系统栏控制**：
- `showSystemNavigationBar` 偏好控制播放器中是否显示系统导航栏
- `showSystemStatusBar` 偏好控制播放器中是否显示系统状态栏
- 使用 `WindowInsets.navigationBars.asPaddingValues()` / `WindowInsets.statusBars.asPaddingValues()` 实现

**安全区域适配**：
- `safeAreaInsetModifier` 在播放器控制布局中应用安全区域内边距
- `navigationBarBottomInsetModifier` 针对底部导航栏额外处理

### 10.5.6 系统状态栏与导航栏

播放器控制布局（`PlayerControls.kt` 第 688~692 行）中：

```kotlin
val navigationBarsPadding =
  if (showSystemNavigationBar) {
    WindowInsets.navigationBars.asPaddingValues()
  } else {
    null
  }
```

若用户选择在播放器中显示系统导航栏，则控制布局会自动留出导航栏空间，避免按钮被系统手势误触。
