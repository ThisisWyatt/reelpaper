## 1. 架构总览

### 1.1 设计目标

- 扩展远程文件浏览器的文件识别能力，支持常见图片格式
- 列表中同时展示文件夹、视频和图片三类内容，类型过滤可自主控制
- 提供全屏图片查看器，支持左右滑动、双击放大、Pinch 缩放、旋转
- 保持现有视频浏览体验不变，老用户默认习惯不受影响
- 采用独立图片缓存层，不复用视频流的 NetworkStreamingProxy 代理架构

### 1.2 技术选型

| 技术点 | 选型 | 理由 |
|--------|------|------|
| 图片查看器手势 | Telephoto `zoomable` 核心模块 (~26 KB) | 成熟的手势体验（边界回弹、fling 惯性、多指协调），代码侵入小 |
| 图片滑动浏览 | Compose Foundation `HorizontalPager` | 官方组件，虚拟化机制成熟 |
| 缩略图磁盘缓存 | `filesDir/thumbnails/network/` | 与视频缩略图共用目录体系，清理策略一致 |
| 大图原图磁盘缓存 | `cacheDir/network_images/` | 独立目录，容量+时间双策略管理 |
| 旋转状态 | 不跨会话持久化 | 实现简单，符合主流图库行为 |

## 2. 文件类型识别

### 2.1 支持的格式

```kotlin
val NETWORK_IMAGE_EXTENSIONS = setOf(
    "jpg", "jpeg", "png", "webp", "gif", "bmp", "heic", "heif", "avif"
)

val NETWORK_IMAGE_MIME_TYPES = setOf(
    "image/jpeg", "image/png", "image/webp", "image/gif",
    "image/bmp", "image/heic", "image/heif", "image/avif"
)
```

### 2.2 识别规则

```kotlin
fun NetworkFile.isNetworkImageFile(): Boolean {
    if (isDirectory) return false
    val lowerName = name.lowercase()
    val ext = lowerName.substringAfterLast('.', "")
    return mimeType in NETWORK_IMAGE_MIME_TYPES ||
        (mimeType == null && ext in NETWORK_IMAGE_EXTENSIONS)
}
```

- 优先通过服务器返回的 `mimeType` 字段判断（以 `image/` 开头）
- 若 `mimeType` 为空，通过文件扩展名后缀匹配支持列表
- 不支持的格式（如 TIFF、RAW）保持忽略

## 3. 网络浏览器列表展示

### 3.1 默认状态

用户点击进入远程文件夹后，列表保持现有体验：**只展示文件夹和视频**。图片文件虽然被识别，但默认隐藏。

### 3.2 展示图片后的列表结构

当用户在「排序与视图选项」中勾选「图片」后，列表分为三个区块依次展示：

1. **文件夹区块** — 与现有行为完全一致
2. **视频区块** — 与现有行为完全一致
3. **图片区块** — 新增，展示当前文件夹内所有图片文件

### 3.3 分类逻辑（NetworkBrowserViewModel）

```kotlin
val folders = filteredFiles.filter { it.isDirectory }
val videos = filteredFiles.filter {
    it.isPlayableNetworkMedia(includeAudio) || it.isNetworkPlaylistFile()
}
val images = filteredFiles.filter {
    it.isNetworkImageFile() && includeImagesInBrowser
}
```

### 3.4 排序行为

- 现有的排序方式（标题、日期、大小）对三类文件同时生效
- 同类型文件内部按当前排序规则排列
- 类型之间的先后顺序固定：文件夹 → 视频 → 图片

### 3.5 搜索行为

- 搜索框输入关键字时，同步过滤图片文件名
- 搜索结果包含文件夹、视频、图片三类匹配项

## 6. NetworkImageRepository 设计

### 6.1 职责

负责通过网络客户端下载远程图片文件到本地私有缓存目录，同时服务缩略图和大图两个场景。

### 6.2 核心接口

```kotlin
class NetworkImageRepository(
    private val context: Context,
) {
    /** 获取缩略图 Bitmap（列表/网格用） */
    suspend fun getThumbnail(
        connectionId: Long,
        path: String,
        lastModified: Long,
        maxSize: Int,
    ): Bitmap?

    /** 获取大图 Bitmap（查看器用） */
    suspend fun getFullImage(
        connectionId: Long,
        path: String,
        lastModified: Long,
        maxDimension: Int = 8192,
    ): Bitmap?

    /** 预加载大图到内存（查看器滑动时调用） */
    suspend fun preloadFullImage(
        connectionId: Long,
        path: String,
        lastModified: Long,
    )

    /** 查看器退出时释放内存缓存 */
    fun clearViewerMemoryCache()

    /** 后台清理过期大图缓存（应用启动时异步执行） */
    fun evictStaleFullImageCache(
        maxAgeDays: Int = 30,
        maxSizeBytes: Long = 500 * 1024 * 1024,
    )
}
```

### 6.3 核心设计

- **下载一次，双重用途**：同一张图片的原图只需下载一次，先写入大图磁盘缓存，缩略图通过采样解码生成后写入缩略图磁盘缓存
- **并发控制**：同一张图片的重复请求自动合并（`inFlightDownloads` 机制）
- **查看器内存缓存**：生命周期与查看器页面绑定，页面退出后释放

### 6.4 缩略图加载流程

```
1. UI 请求缩略图
2. 检查缩略图磁盘缓存 → 命中则直接解码返回
3. 未命中则检查大图原图磁盘缓存 → 命中则采样生成缩略图，存入缩略图缓存后返回
4. 均未命中则通过 NetworkClient.getFileStream() 下载远程原图
5. 原图存入大图磁盘缓存
6. 采样解码生成缩略图，存入缩略图磁盘缓存
7. 返回缩略图 Bitmap 给 UI
```

### 6.5 大图加载流程

```
1. UI 请求大图
2. 检查查看器内存缓存 → 命中直接返回
3. 检查大图磁盘缓存 → 命中则加载到内存并返回
4. 检查是否有正在下载的同一张图 → 等待
5. 通过 NetworkClient.getFileStream() 下载远程原图
6. 写入大图磁盘缓存 + 查看器内存缓存
7. 返回大图 Bitmap 给 UI
```

### 6.6 缓存键设计

```kotlin
private fun cacheKey(path: String, lastModified: Long): String {
    val input = "$path|$lastModified"
    return MessageDigest.getInstance("SHA-256")
        .digest(input.toByteArray())
        .joinToString("") { "%02x".format(it) }
}
```

使用 `path + lastModified` 作为哈希输入，当远程文件被修改时缓存自动失效。

## 7. 缓存策略

### 7.1 缩略图缓存

| 属性 | 值 |
|------|-----|
| 尺寸 | 列表模式约 128px~256px 长边，网格模式按屏幕密度动态计算 |
| 内存缓存 | LRU，按应用可用内存的 1/32 分配 |
| 磁盘缓存 | `filesDir/thumbnails/network/`，以 SHA-256 哈希作为文件名，JPEG 压缩存储 |
| 清理策略 | 无限增长 + 手动清理（通过设置页面的「清除缓存」触发） |
| 失效机制 | 当远程文件被修改（`lastModified` 变化）时，缓存自动失效 |
| 生成方式 | 下载原图后通过 `BitmapFactory.Options.inSampleSize` 采样解码生成 |

### 7.2 大图原图缓存

| 属性 | 值 |
|------|-----|
| 尺寸 | 展示原图分辨率，不做人为压缩。极端大图（超过 8192px 长边）采样加载 |
| 磁盘缓存 | `cacheDir/network_images/`，以 SHA-256 哈希作为文件名，按原图格式存储 |
| 清理策略 | 容量 + 时间双策略：最大 500MB，超出按 LRU 淘汰；超过 30 天未访问自动清理 |
| 触发时机 | 应用启动时异步执行一次过期扫描 |
| 按需加载 | 用户未点击查看的图片不预加载原图；点击后加载当前张，同时预加载左右相邻两张 |

### 7.3 查看器内存缓存

| 属性 | 值 |
|------|-----|
| 生命周期 | 查看器页面存活期间保留，退出后释放 |
| 大小 | 按可用内存的 1/16 分配 LRU |
| 占位策略 | 滑动到尚未加载完成的图片时，先展示该图片的缩略图作为占位，大图加载完成后平滑替换 |

### 7.4 缓存清理

- 应用升级或缓存目录异常时，自动清理损坏或无法解码的缓存文件
- 缩略图缓存跟随视频缩略图一起被「清除缓存」功能清理
- 大图原图缓存不提供单独的用户手动清理入口（由系统自动按容量/时间策略管理）

## 8. 图片查看器设计

### 8.1 进入方式

点击图片卡片 → 进入全屏图片查看器（新页面，全屏沉浸模式）。

### 8.2 Screen 定义

```kotlin
@Serializable
data class ImageViewerScreen(
    val connectionId: Long,
    val connectionName: String,
    val folderPath: String,
    val initialImagePath: String,
    val imagePaths: List<String>,
) : Screen
```

- `imagePaths`：当前过滤条件下所有图片的路径列表（滑动范围限定在当前过滤结果内）
- `initialImagePath`：用户点击的那张图片的初始位置

### 8.3 核心功能

| 功能 | 交互方式 | 实现要点 |
|------|----------|----------|
| 左右滑动切换 | 横向滑动手势 | `HorizontalPager`，按当前排序顺序浏览 |
| 双击放大/还原 | 双击屏幕 | Telephoto `zoomable` 的 `onDoubleClick = { toggleZoom() }` |
| 双指捏合缩放 | Pinch 手势 | Telephoto `zoomable` 自动处理 |
| 旋转 | 旋转按钮 | `graphicsLayer { rotationZ = rotation }`，每次顺时针 +90° |
| 返回 | 系统返回手势 / 按钮 | 退出查看器，回到文件列表 |

### 8.4 预加载策略

#### 缩略图预加载（进入查看器时）

查看器初始化时**全量预加载所有图片的缩略图**，但采用分批控制避免并发过载：

```kotlin
// 故意设计为全量加载：用户滑动到任意页面时，缩略图已就绪可作为 placeholder 展示
// 分批大小 5，一批完成后再加载下一批，避免同时发起过多网络/磁盘请求
viewModelScope.launch {
    images.chunked(THUMBNAIL_BATCH_SIZE).forEach { batch ->
        batch.map { file -> async { loadThumbnail(file) } }.awaitAll()
    }
}
```

> **设计说明**：这不是 bug。缩略图全量预加载是为了保证用户左右滑动时，每一页都能立即显示低清缩略图作为占位，大图加载完成后再平滑替换。缩略图体积小（256×256 像素量级），即使 100 张图片的文件夹，全量加载也远快于逐张大图下载。真正需要按需控制的是**大图原图**的加载。

#### 大图原图预加载（滑动过程中）

```kotlin
LaunchedEffect(pagerState.currentPage) {
    val prev = (pagerState.currentPage - 1).coerceAtLeast(0)
    val next = (pagerState.currentPage + 1).coerceAtMost(imagePaths.size - 1)
    viewModel.preloadImage(imagePaths[prev])
    viewModel.preloadImage(imagePaths[next])
}
```

**仅预加载当前页的前一张和后一张大图原图**。大量图片时只保留当前页及相邻页的 Bitmap，避免内存溢出。

### 8.5 滑动范围

仅浏览当前文件夹内、且在当前过滤条件下可见的图片。例如：用户通过搜索筛选后点击图片，滑动范围限定在搜索结果中的图片。

### 8.6 旋转状态

旋转状态**不跨会话持久化**。每次打开查看器都按原图方向展示，旋转仅在当前查看会话内有效。退出查看器后再次进入同一张图片，恢复为原始方向。

## 9. 与现有组件的关系

| 现有组件 | 关系说明 |
|----------|----------|
| `RemoteImageLoader` | 共存但不耦合。`RemoteImageLoader` 继续负责 Jellyfin/Navidrome 等 HTTP 图片加载；`NetworkImageRepository` 负责远程协议（WebDAV/SMB/FTP/SFTP）图片加载。两者缓存目录分离。 |
| `NetworkBrowserScreen` | 扩展：新增图片区块渲染逻辑，复用现有的列表/网格布局框架。 |
| `NetworkBrowserViewModel` | 扩展：新增图片文件识别逻辑（`isNetworkImageFile`），文件加载流程不变。 |
| `ThumbnailRepository` | 图片缩略图磁盘缓存接入现有 `ThumbnailRepository` 的磁盘目录体系（`filesDir/thumbnails/network/`），清理策略与视频缩略图保持一致。图片缩略图的生成逻辑由 `NetworkImageRepository` 处理（采样解码原图），不通过视频帧提取。 |
| `NetworkStreamingProxy` | **不使用**。图片加载绕过代理层，直接通过网络客户端下载。 |

## 10. 边界情况与异常处理

### 10.1 过滤与空状态

| 场景 | 预期行为 |
|------|----------|
| 勾选图片但当前文件夹无图片 | 列表展示文件夹 + 视频。若当前文件夹无图片，不显示图片区块 |
| 取消勾选图片 | 列表只展示文件夹 + 视频，图片区块隐藏 |
| 搜索状态下无图片匹配 | 搜索结果为空时，显示搜索空状态 |

### 10.2 图片查看器边界情况

| 场景 | 预期行为 |
|------|----------|
| 单张图片文件夹 | 进入查看器后左右滑动无效（只有一张），不显示滑动指示器 |
| 大量图片文件夹（500+ 张） | 查看器采用虚拟化机制，只保留当前页及相邻页的 Bitmap |
| 图片加载失败 | 显示错误占位图，允许用户重试，不影响滑动到其他图片 |
| 网络断开 | 查看器内已缓存的图片可正常浏览；未缓存的图片显示断网提示 |
| 大图已被清理、只剩缩略图 | 先展示缩略图作为占位，同时后台重新下载原图；下载完成后平滑过渡 |
| 滑动到边界 | 到达第一张或最后一张时，提供视觉边界反馈（回弹） |

### 10.3 格式与兼容性

| 场景 | 预期行为 |
|------|----------|
| GIF 动图 | 列表和查看器中均展示静态首帧，暂不支持动画播放 |
| 不支持的格式（TIFF、RAW 等） | 不识别为图片，保持忽略状态 |
| 图片文件损坏 | 解码失败时显示错误占位图，不崩溃 |
| 图片尺寸极大（如 100MP） | 查看器加载时做上限保护（超过 8192px 长边则采样加载），避免 OOM |

### 10.4 安全与隐私

- 图片缓存存储在应用私有目录，不进入系统相册，不暴露给用户或其他应用
- 网络客户端访问远程图片时，复用已有的连接认证信息，不额外请求权限
- 图片查看器不记录浏览历史或截图

## 11. 性能要求

| 指标 | 目标 |
|------|------|
| 缩略图加载 | 列表滚动时，图片缩略图应在 300ms 内完成首次展示（命中缓存时立即展示） |
| 查看器滑动 | 相邻图片预加载完成后，左右滑动切换应达到 60fps，无明显卡顿 |
| 内存占用 | 浏览包含 1000 张图片的文件夹时，内存增长不超过 50MB（依赖虚拟化和采样机制） |

---

## 12. 兼容性要求

- 最低支持 Android API 与现有应用保持一致（minSdk = 26）
- 支持 WebDAV、SMB、FTP、SFTP 四种远程协议的图片加载
- 图片查看器手势在 TV 模式下（遥控器/手柄操作）可降级为按钮切换
