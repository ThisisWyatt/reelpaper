# 网络播放与流媒体——技术实现说明

> 本文档基于 mpvRx 项目源码（`app/src/main/java/app/gyrolet/mpvrx/data/network/` 及关联模块）编写，所有技术细节均从代码中提取，未做无依据的推断。

---

## 一、总体架构

网络播放与流媒体模块位于 `data/network/` 包下，核心职责分为三层：

1. **协议客户端层**（`client/`）：为 SMB、FTP、WebDAV、SFTP 四种协议提供统一的 `NetworkClient` 抽象，负责目录浏览、文件大小探测、范围流读取。
2. **本地代理层**（`proxy/`）：基于 NanoHTTPD 在 `127.0.0.1` 随机端口上构建环回代理，将协议客户端的流转换为带 Capability Token 鉴权的 HTTP 流，供 libmpv 消费。
3. **在线流层**（`proxy/` + `utils/media/`）：通过 `HlsStreamingProxy` 代理 HLS/M3U8 流，通过 `XtreamStreamingProxy` 代理 Xtream Codes IPTV 流，并支持 M3U 播放列表解析。

凭证安全由 `credentials/NetworkCredentialCipher.kt` 与 `AndroidNetworkCredentialKey` 负责，采用 AES-256-GCM + Android Keystore 存储网络连接密码。

核心设计决策：

- **凭证隔离**：`mpvrx-network://` URI 中绝不包含密码，仅携带连接 ID 和路径
- **本地代理转接**：libmpv 实际请求的是 `http://127.0.0.1:<随机端口>/<token>/<path>`，代理负责鉴权并转发到远程
- **Capability Token**：每个注册流获得密码学随机 token，同一 token 可解析同连接下的 sibling 路径（用于 HLS 片段、密钥等）

## 二、网络存储协议支持

### 2.1 协议抽象层

**源码位置**：
- `data/network/client/NetworkClient.kt`
- `data/network/client/NetworkClientFactory.kt`
- `domain/network/NetworkConnection.kt`

#### NetworkClient 接口

所有协议客户端均实现 `NetworkClient` 接口，定义如下：

```kotlin
interface NetworkClient {
  suspend fun connect(): Result<Unit>
  suspend fun disconnect()
  fun isConnected(): Boolean
  suspend fun listFiles(path: String): Result<List<NetworkFile>>
  suspend fun getFileStream(path: String, offset: Long = 0L): Result<InputStream>
  suspend fun getFileSize(path: String): Result<Long>
  suspend fun getFileUri(path: String): Result<Uri>
}
```

其中 `getFileSize` 有默认实现返回 `UnsupportedOperationException`，各协议按需覆盖；`getFileUri` 返回**不含凭证**的源站 URI（如 `sftp://host/path`），仅用于诊断或匿名源，认证播放必须通过代理。

#### 协议工厂

`NetworkClientFactory.createClient()` 根据 `NetworkConnection.protocol` 分发：

```kotlin
when (connection.protocol) {
  NetworkProtocol.SMB -> SmbClient(connection)
  NetworkProtocol.FTP -> FtpClient(connection)
  NetworkProtocol.WEBDAV -> WebDavClient(connection)
  NetworkProtocol.SFTP -> SftpClient(connection)
}
```

#### 网络连接模型

`NetworkConnection` 是 Room 实体（`@Entity(tableName = "network_connections")`），字段包括：

- `id`, `name`, `protocol`, `host`, `port`, `username`, `password`, `path`, `isAnonymous`, `lastConnected`, `autoConnect`, `useHttps`

`toString()` 会红显密码（输出 `credentials=<redacted>`），防止日志泄露。

#### 路径规范化

`NetworkPath` 是 `@JvmInline value class`，确保：
- 不包含 scheme、authority、凭证、父目录遍历（`..`）
- 显示形式以 `/` 开头（如 `/Movies/video.mkv`）
- 最大路径长度 32,768 字符，最大段数 512，单段最大 1,024 字符

#### 无凭证持久化引用（NetworkPlaybackUri）

**源码位置**：`domain/network/NetworkPath.kt`

自定义 scheme：

```
mpvrx-network://{connectionId}{path}
```

示例：
```
mpvrx-network://42/Movies/video.mkv
```

- **Scheme**: `mpvrx-network`（硬编码常量）
- **Authority**: 连接 ID（`Long`，必须 > 0）
- **Path**: 规范化后的网络路径（以 `/` 开头，不含 `..`、`.`、控制字符）
- **禁止字段**: `userInfo`、`port`、`query`、`fragment` 均为 `null`

与常见 URI 类型的对比：

| URI 类型 | 用途 | 凭证携带 | 持久化安全 |
|---------|------|---------|-----------|
| `mpvrx-network://` | 网络文件引用 | 否（仅 connectionId） | 安全（密码存 Room + Keystore） |
| `content://` | Android ContentProvider | N/A | N/A |
| `fd://` | 临时文件描述符 | N/A | 单次使用，不可持久化 |
| `http(s)://` | 直接 URL / HLS | 可能（URL 中） | 不安全 |

### 2.2 WebDAV 客户端

**源码位置**：`data/network/client/WebDavClient.kt`

- **依赖库**：`com.thegrizzlylabs.sardineandroid`（OkHttpSardine）
- **HTTP/HTTPS**：通过 `connection.useHttps` 控制 scheme
- **认证**：Basic Auth，匿名连接跳过 `Authorization` 头
- **共享 HTTP 客户端**：使用 `SharedHttpClient.derive { callTimeout(0, TimeUnit.SECONDS) }`，避免 10 秒读超时杀死健康长流

#### 连接建立

```kotlin
override suspend fun connect(): Result<Unit> {
  val candidate = OkHttpSardine()
  if (!connection.isAnonymous) {
    candidate.setCredentials(connection.username, connection.password)
  }
  // 可达性探测：仅 401/403 视为致命失败
  try {
    candidate.list(buildUrl("", trailingSlash = true), 0)
  } catch (probeError: SardineException) {
    if (probeError.statusCode == 401 || probeError.statusCode == 403) throw probeError
  }
  sardine = candidate
}
```

**设计意图**：反向代理常拒绝根路径的 PROPFIND，但不影响下层文件访问，因此仅认证错误才中止连接。

#### 文件列表（PROPFIND）

```kotlin
override suspend fun listFiles(path: String): Result<List<NetworkFile>> {
  val resources = client.list(directoryUrl.toString())
  return resources
    .mapNotNull { resource -> toImmediateChild(resource, directory, directoryUrl) }
    .distinctBy(NetworkFile::path)  // 去重：部分服务器返回重复 href
}
```

**子项识别策略**（`toImmediateChild`）：
1. 优先通过 href URI 解析精确匹配子路径
2. 回退到 Sardine 解码后的 `resource.name`
3. 排除自身目录响应（集合自引用）
4. 排除含编码路径分隔符（`%2f`、`%5c`）的异常 href

#### 文件大小探测

WebDavClient 采用**三级探测策略**：

```
1. PROPFIND getcontentlength（最可靠）
   ↓ 失败/缺失
2. HTTP HEAD → Content-Length（兼容混合 HTTP/DAV 服务器）
   ↓ 失败/缺失
3. HTTP Range: bytes=0-0 → Content-Range（终极回退）
```

代码实现见 `probeSizeOverHttp()` 方法（第 226-257 行）。

#### URL 构建

```kotlin
private fun buildHttpUrl(relativePath: String, trailingSlash: Boolean = false): HttpUrl {
  val builder = HttpUrl.Builder()
    .scheme(if (connection.useHttps) "https" else "http")
    .host(host)
    .port(connection.port)
  // 分别添加 connection.path 和 relativePath 的 segments
  // 避免 URI 双重编码问题
}
```

**关键设计**：使用 OkHttp 的 `HttpUrl.Builder.addPathSegment()` 逐段编码，确保 `[`、`]`、`%`、`#`、`?`、空格等特殊字符只编码一次。

#### 流式读取与 Seek

```kotlin
override suspend fun getFileStream(path: String, offset: Long): Result<InputStream> {
  if (offset > 0L) {
    return getRangedFileStream(path, offset)  // 自定义 InputStream，支持跨段续传
  }
  // offset == 0：直接 GET，无 Range
  val requestBuilder = Request.Builder().url(buildUrl(path)).get()
    .header("Accept-Encoding", "identity")  // 禁止压缩，确保 Range 准确
  ...
}
```

**Range InputStream 设计**（`getRangedFileStream`）：
- 当当前段耗尽时，自动发起下一段 Range 请求
- 检测资源总长度变化（如文件被替换），抛出 `IOException`
- 每段响应独立关闭，避免连接泄漏

**200 降级处理**：部分 DAV 服务器忽略 Range 返回 200，代理通过 `skipExactly()` 跳过前 `offset` 字节，保持 seek 功能可用

### 2.3 SMB 客户端

**源码位置**：`data/network/client/SmbClient.kt`

- **依赖库**：`com.hierynomus.smbj`（SMBJ）
- **dialect 支持**：SMB 3.1.1、3.0.2、3.0、2.1、2.0.2
- **配置**：
  - 传输缓冲区 512 KiB（`SMB_TRANSPORT_BUFFER_SIZE`），流缓冲区 256 KiB（`SMB_STREAM_BUFFER_SIZE`）
  - DFS 禁用，`multiProtocolNegotiate = true`，`signingRequired = false`，`encryptData = false`
  - 超时 60 秒
- **连接**：15 秒 `withTimeout`，要求配置路径仅为 share 名（不含子目录）
- **单请求重试**：`executeWithRetry()` 检测网络错误（`TimeoutException`、`TransportException`、`SMBRuntimeException`、`SocketException`、`EOFException`），在 session 引用未变时自动断开重连一次
- **文件句柄隔离**：`getFileStream()` 每次 `openFile()` 获取独立句柄，关闭时仅关闭句柄，不关闭 DiskShare（DiskShare 是 session 缓存的树连接，关闭会中断并发流）

### 2.4 FTP 客户端

**源码位置**：`data/network/client/FtpClient.kt`

- **依赖库**：`org.apache.commons.net.ftp.FTPClient`
- **模式**：BINARY + 被动模式（`enterLocalPassiveMode()`）
- **UTF-8**：连接成功后发送 `OPTS UTF8 ON`（忽略失败）
- **连接超时**：控制连接 15 秒；流传输时数据超时 2 分钟，控制保活 10 分钟
- **流隔离**：每次 `getFileStream()` 新建独立 FTPClient，单独连接、登录、设置偏移（`setRestartOffset(offset)`）
- **连接健康检查**：`listFiles()` 前通过 `sendNoOp()` 检测连接，失败则自动重连

### 2.5 SFTP 客户端

**源码位置**：`data/network/client/SftpClient.kt`

- **依赖库**：`com.jcraft.jsch`（JSch）
- **认证**：`publickey,keyboard-interactive,password` 顺序，跳过 GSSAPI/Kerberos 避免协商阻塞
- **StrictHostKeyChecking**：`no`
- **连接探测**：连接后通过 `withChannel` 对 base path 执行 `stat` 验证是目录
- **并发 Range 流隔离**：`getFileStream()` 为每个流新建独立 `ChannelSftp`，因为 `ChannelSftp` 内部序列化请求管道；流关闭时独立断开 channel
- **符号链接解析**：`toNetworkFile()` 对 `isLink` 条目通过 `channel.stat()` 解析目标属性

### 2.6 自动连接

**源码位置**：`App.kt`、`repository/NetworkRepository.kt`、`database/dao/NetworkConnectionDao.kt`

- `NetworkConnection` 有 `autoConnect: Boolean = false` 字段
- `NetworkConnectionDao` 提供 `@Query("SELECT * FROM network_connections WHERE autoConnect = 1 ORDER BY id ASC")`
- `App.autoConnectNetworksOnce()` 在应用启动后延迟 500ms 执行，使用 `AtomicBoolean` 保证仅执行一次，在 `applicationScope` 中遍历 `autoConnect = 1` 的连接并调用 `NetworkRepository.connect()`
- 失败仅记录日志，不阻塞其他连接

### 2.7 网络书签

**源码位置**：`preferences/NetworkBookmarkPreferences.kt`

- 基于 `PreferenceStore` 的键值存储，key 为 `"network_folder_bookmarks"`
- 存储类型为 `List<NetworkFolderBookmark>`（Kotlinx Serialization JSON 序列化）
- `NetworkFolderBookmark` 包含 `connectionId`、`path`、`folderName`
- 提供 `toggle()`、`remove()`、`removeForConnection()`、`contains()` 操作
- UI 层通过 `NetworkBookmarksScreen` 展示书签列表，支持快速跳转

### 3.4 播放启动流程

点击文件后，`playVideoInternal()` 执行：

```kotlin
private fun playVideoInternal(connection: NetworkConnection, file: NetworkFile) {
  // 1. 收集当前目录中所有可播放文件作为队列
  val playableFiles = currentDirectoryPlayableFiles(file)
  val playlistIndex = playableFiles.indexOfFirst { it.path == file.path }

  // 2. 为每个文件创建 PlaybackItem
  val queueItems = playableFiles.map { networkFile ->
    val networkUri = NetworkPlaybackUri.create(connection.id, networkFile.path)
    PlaybackItem.fromUri(
      uri = networkUri,
      title = networkFile.name,
      mimeType = networkFile.mimeType,
      networkSource = NetworkPlaybackSource(connection.id, networkFile.path),
    )
  }

  // 3. 暂存播放队列
  val launchToken = PreparedPlaybackLaunchStore.stage(
    items = queueItems,
    currentIndex = playlistIndex,
    isExplicitQueue = true,
  )

  // 4. 启动 PlayerActivity
  val intent = Intent(Intent.ACTION_VIEW, uri)
  intent.setClass(application, PlayerActivity::class.java)
  intent.putExtra(PlayerActivity.EXTRA_PREPARED_PLAYBACK_QUEUE, true)
  intent.putExtra(PlayerActivity.EXTRA_PREPARED_PLAYBACK_TOKEN, launchToken)
  intent.putExtra("network_connection_id", connectionId)
  intent.putExtra("network_file_path", file.path)
  application.startActivity(intent)
}
```

### 3.5 M3U 播放列表支持

```kotlin
private suspend fun openM3uFile(connection: NetworkConnection, file: NetworkFile) {
  val client = repository.createClient(connection.id).getOrThrow()
  val parseResult = M3UParser.parseFromStream(
    inputStream = client.getFileStream(file.path).getOrThrow(),
    sourceUrl = NetworkPlaybackUri.create(connection.id, file.path),
    overridePlaylistName = file.name,
  )

  // 判断是否为直接可播的 HLS
  if (M3UParser.shouldPlayHlsDirectly(parseResult)) {
    playVideoInternal(connection, file)
    return
  }

  // 导入为 Room 持久化播放列表
  val persistentResult = parsed.copy(
    items = parsed.items.map { item -> item.forSavedConnection(connection) }
  )
  val playlistId = playlistRepository.createM3UPlaylistFromParsed(persistentResult, file.name)
  _importedPlaylistId.emit(playlistId.toInt())  // 导航到 PlaylistDetailScreen
}
```

**M3U 项持久化转换**（`forSavedConnection`）：
- 若 M3U 中的 URL 已经是 `mpvrx-network://` 且属于同一连接，保留原样
- 否则尝试解析为绝对路径，转换为 `mpvrx-network://` 格式
- 外部 URL（不属于当前连接的）保留原始 URL（经 `M3UParser.sanitizeSourceUrl` 处理）

## 四、网络播放代理架构

### 4.1 总体设计

**源码位置**：`data/network/proxy/NetworkStreamingProxy.kt`

`NetworkStreamingProxy` 是继承 NanoHTTPD 的单例类，绑定 `127.0.0.1:0`（随机端口）。设计目标：

- 将 SMB/FTP/WebDAV/SFTP 的协议原生流转为本地 HTTP 流
- 通过密码学随机 Token 鉴权，URL 中不携带远程凭证
- 支持 sibling 路径解析（HLS 分片、密钥、map 文件等相对引用）

#### 核心数据结构

```kotlin
private class StreamInfo(
  val connectionId: Long,
  val primaryPath: NetworkPath,
  fileSize: Long,
  val primaryMimeType: String,
) {
  val knownSizes = ConcurrentHashMap<NetworkPath, Long>()
  val clientMutex = Mutex()
  @Volatile var client: NetworkClient? = null
}
```

`knownSizes` 缓存文件大小，避免每次 range 请求前重复探测；`clientMutex` 保证同一线程内串行化连接与重连。

### 4.2 Capability Token

- **长度**：24 字节随机数（`SecureRandom.nextBytes(ByteArray(24))`）
- **编码**：URL-safe Base64（无填充）
- **URL 格式**：`http://127.0.0.1:{port}/{token}{path}`
- **替换策略**：同一 `streamId` 重新注册时，旧 token 对应的 `StreamInfo` 会被异步关闭

### 4.3 HTTP 请求处理流程

```
libmpv 请求 → NanoHTTPD.serve() → parseRoute() → 验证 token
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
                 HEAD 请求        GET + Range        GET 完整
                    │                 │                 │
                    ▼                 ▼                 ▼
              HeadResponse      handleRangeRequest   handleFullRequest
              (Accept-Ranges)        │                 │
                                     ▼                 ▼
                              getFileSize()        getFileSize()
                              getStream()          getStream()
                                     │                 │
                                     └────────┬────────┘
                                              ▼
                                    withConnectedClient()
                                              │
                                    ┌─────────┴─────────┐
                                    ▼                   ▼
                              createClient()      connect()
                                    │
                                    ▼
                            WebDavClient/SmbClient/FtpClient
```

### 4.4 Range 请求支持

**源码位置**：`data/network/proxy/HttpByteRange.kt`

NanoHTTPD 的 `serve()` 解析 `Range` 头，通过 `HttpByteRange.parse()` 处理：

- 语法：`bytes=(\d*)-(\d*)`
- 支持前缀范围（`bytes=start-end`）和后缀范围（`bytes=-suffixLength`）
- 返回 206 Partial Content，带 `Content-Range` 和 `Accept-Ranges: bytes`

对返回 200（非 206）的上游服务器，WebDAV 客户端在 `openRangedResponse()` 中自动降级为 skip 策略：跳过前 `offset` 字节后返回完整流。

### 4.5 三级大小探测

WebDAV 客户端 `probeSizeOverHttp()` 的三级 fallback：

1. PROPFIND `contentLength`
2. HEAD `Content-Length`
3. `Range: bytes=0-0` 的 `Content-Range` 响应头

代理层 `getFileSize()` 会将结果缓存到 `StreamInfo.knownSizes`，避免重复探测。

### 4.6 代理超时与生命周期

- **操作超时**：`PROXY_OPERATION_TIMEOUT_SECONDS = 75L`，`awaitProxyIo()` 使用 `CountDownLatch` 等待协程结果，超时时取消 job 并丢弃迟到的流
- **连接管理**：`withConnectedClient()` 懒创建/重连 `NetworkClient`，操作失败时检测 `isConnected()`，若已断开则驱逐缓存
- **流关闭**：`unregisterStream()` 触发 `closeAsync()`，在 `NonCancellable` 上下文中释放客户端连接
- **清理**：`stopInstance()` 清空所有 token/流映射，取消 `proxyScope`

## 六、HLS 与在线流

### 6.1 HLS 代理

**源码位置**：`data/network/proxy/HlsStreamingProxy.kt`

`HlsStreamingProxy` 同样继承 NanoHTTPD，绑定 `127.0.0.1:0`。

#### 注册与 URL 结构

```kotlin
fun registerStream(streamId, sourceUrl, headers, userAgent): String
// 返回: http://127.0.0.1:{port}/hls/{token}/master.m3u8
```

#### 请求路由

| 子路径 | 处理逻辑 |
|--------|----------|
| `master.m3u8` | 拉取源站 master manifest，重写 variant/media URL 为本地代理 URL |
| `variant.m3u8?r={token}` | 拉取 variant manifest，重写 segment/key/map URL |
| `segment?r={token}` | 拉取媒体分片，支持 Range，透传 206/200 |
| `key?r={token}` | 拉取加密密钥 |

#### Manifest 重写

- **Master**：解析 `#EXT-X-STREAM-INF:` 后的 variant URL 和 `#EXT-X-MEDIA:` 的 `URI="..."`，替换为 `/hls/{token}/variant.m3u8?r={targetToken}`
- **Variant**：解析 `#EXT-X-KEY:` 的 `URI`、`#EXT-X-MAP:` 的 `URI`、segment URL，分别替换为 `/hls/{token}/key?r=...` 和 `/hls/{token}/segment?r=...`
- **相对 URL 解析**：使用 OkHttp 的 `HttpUrl.resolve()` 基于最终请求 URL 解析
- **跨域安全**：`credentialsFor()` 仅当目标 URL 与 source URL 同 scheme+host+port 时才转发 `Authorization`/`Cookie` 头
- **CORS**：所有响应带 `Access-Control-Allow-Origin: *`

#### 目标 URL 缓存

每个 `HlsSession` 内部维护：
- `targetUrlsByToken`: LinkedHashMap（LRU，访问顺序），最大 8,192 条（`MAX_TARGETS_PER_SESSION`）
- `targetTokensByUrl`: 反向索引，避免重复注册同一 URL

### 6.2 M3U 播放列表解析

**源码位置**：`utils/media/M3UParser.kt`

`M3UParser` 是单例对象，支持三种入口：

- `parseFromUrl()`: HTTP(S) 加载，30 秒超时，自动提取 URL user-info 转为 `Authorization: Basic` 头，然后从 URL 中抹除凭证
- `parseFromUri()`: 本地/content URI 加载
- `parseFromStream()`: 通用流解析

#### 解析能力

- **安全限制**：默认最大 32 MiB、300,000 行、100,000 条目（`M3ULimits`）
- **格式支持**：`#EXTM3U`、`#EXTINF:`（含属性解析，如 `tvg-id`、`tvg-name`、`tvg-logo`、`group-title`）、`#KODIPROP:`（license_type/license_key）、`#EXTVLCOPT:`（`http-user-agent`）
- **HLS 检测**：内容含 `#EXT-X-` 行时返回错误 `HLS_ERROR`，由调用方决定直接播放或走 HLS 代理
- **URL 安全**：`sanitizeSourceUrl()` 移除 `user:password@`；`resolveMediaUrl()` 将相对路径解析为绝对 URL

#### HLS 播放策略

**源码位置**：`ui/player/M3uPlaybackPolicy.kt`

```kotlin
fun shouldProxyHls(playableUri, mimeType, enableHlsProxy): Boolean
```

条件：
- `enableHlsProxy = true`
- scheme 为 `http://` 或 `https://`
- 非本地回环（不含 `127.0.0.1` 或 `localhost`）
- URL 含 `.m3u8`、或 MIME type 含 `mpegurl`、或路径含 `/hls/`、或含 `=m3u8`、或含 `format=m3u8`

### 6.3 Xtream Codes 代理

**源码位置**：`data/network/XtreamClient.kt`、`data/network/proxy/XtreamStreamingProxy.kt`

#### XtreamClient

- 验证账号：调用 `player_api.php?username=...&password=...`，解析 JSON 的 `user_info.auth` 和 `status`
- 加载目录：`get.php?type=m3u_plus&output=ts`，通过 `M3UParser.parseFromUrl()` 解析
- 用户代理固定为 `mpvRx/2.5`
- 认证响应限制 512 KiB

#### XtreamStreamingProxy

- Token 机制与 `NetworkStreamingProxy` 相同（24 字节随机，URL-safe Base64）
- URL 格式：`http://127.0.0.1:{port}/xtream/{token}/stream.{extension}`
- **源站解析**：`resolveSource()` 通过 `PlaylistRepository.resolveXtreamStream()` 异步解析，30 秒超时，结果缓存到 `StreamInfo.sourceUrl`
- **HLS 回退**：若 `extension = "m3u8"` 或上游返回 HLS 内容类型，则重定向到 `HlsStreamingProxy`
- **Range 透传**：将 mpv 的 `Range` 头直接转发给上游

### 6.4 三种代理的协同

PlaybackSession 的 `resolvePlayableUri` 同时处理三种网络代理：

| 代理类型 | 用途 | 注册方法 |
|---------|------|---------|
| `NetworkStreamingProxy` | WebDAV/SMB/FTP 本地文件 | `registerStream(streamId, connectionId, filePath, ...)` |
| `HlsStreamingProxy` | HLS/M3U8 流媒体代理 | `registerStream(streamId, sourceUrl, headers, userAgent)` |
| `XtreamStreamingProxy` | Xtream Codes IPTV | `registerStream(streamId, reference, headers, mimeType)` |

三种代理共享同一套 `NetworkStreamRegistration` 结构，由 `releaseNetworkStream()` 统一释放：

```kotlin
private fun releaseNetworkStream(registration: NetworkStreamRegistration) {
  registration.proxy?.unregisterStream(registration.streamId)
  registration.hlsProxy?.unregisterStream(registration.streamId)
  registration.xtreamProxy?.unregisterStream(registration.streamId)
}
```

### 7.3 明文迁移

**源码位置**：`repository/NetworkRepository.kt`

`NetworkRepository` 负责密码的存储和解析，完整生命周期如下：

```
UI 输入明文密码
    │
    ▼
addConnection() / updateConnection()
    │
    ▼
encryptForStorage() ──→ AES/GCM 加密 ──→ 密文存入 Room
    │
    ▼
redactAndMigrate() ──→ UI 返回 password=""（红码处理）
    │
    ▼
createClient() / resolveCredential()
    │
    ▼
decrypt() ──→ 明文密码仅存在于内存中的 NetworkClient
```

自动迁移策略：

1. **`getAllConnections()` / `getAutoConnectConnections()` / `getConnectionById()`**：通过 `redactAndMigrate()` 读取时，若 `password.isNotEmpty() && !credentialCipher.isEncrypted(password)`，则调用 `migratePlaintextPasswordLocked()` 加密后更新数据库
2. **`updateConnection()`**：更新连接时，若现有密码非加密格式，同样触发迁移
3. **`resolveCredential()`**：创建客户端前解密时，若密码非加密格式，先迁移再解密

迁移失败时保留原始行，下次读取/使用时重试，避免数据丢失。

## 八、关键设计决策与权衡

### 8.1 为何使用本地代理而非直接 URL？

| 方案 | 优点 | 缺点 | mpvRx 选择 |
|------|------|------|-----------|
| 直接 URL（含凭证） | 简单 | 凭证暴露在 mpv 日志、崩溃报告、播放列表中 | ❌ |
| 直接 URL（无凭证，依赖服务器匿名） | 安全 | 不适用需要认证的私有服务器 | ❌ |
| **本地代理** | 凭证隔离、支持 Range、可处理 sibling 路径 | 增加一层跳转、需要维护 NanoHTTPD | ✅ |

### 8.2 为何使用 NanoHTTPD 而非系统 HTTP 服务器？

- **零配置**：无需网络权限声明（仅绑定 127.0.0.1）
- **轻量**：单文件嵌入式 HTTP 服务器
- **可控**：完全掌握 Range、MimeType、Connection 关闭行为

### 8.3 为何 NetworkPlaybackUri 使用自定义 scheme？

- **语义明确**：明确标识这是一个"需通过代理解析的网络引用"
- **安全**：scheme 级别禁止包含 userInfo、query、fragment
- **持久化友好**：可安全存入 Room、播放列表、Intent Extra 而不泄露凭证

### 8.4 WebDavClient 的 Range 回退策略

部分老旧或混合 HTTP/DAV 服务器不完全支持 RFC 7233 Range 请求。WebDavClient 在以下情况提供回退：

1. **服务器返回 200（忽略 Range）**：通过 `skipExactly()` 跳过前导字节，保持 seek 功能可用
2. **PROPFIND 不提供长度**：回退到 HTTP HEAD → HTTP Range 探测
3. **连接超时**：`rangeHttpClient` 使用 `callTimeout(0)`，避免长媒体流被切断
