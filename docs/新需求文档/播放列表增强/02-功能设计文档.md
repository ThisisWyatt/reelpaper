# 播放列表网络视频支持 — 功能设计文档

## 1. 架构概述

本功能在现有播放列表体系上进行扩展，**不引入新的播放架构**，核心原则是：
- 数据层：复用 `NetworkPlaybackUri` 作为网络文件的唯一标识
- 播放层：完全复用 `NetworkStreamingProxy`，零改动
- UI 层：在现有组件上增加选择模式与来源切换

#### Room Migration

```kotlin

val MIGRATION_N_TO_NPLUS1 = object : Migration(N, N + 1) {
  override fun migrate(db: SupportSQLiteDatabase) {
    // 1. 新增 connectionId 列
    db.execSQL("ALTER TABLE playlist_items ADD COLUMN connectionId INTEGER DEFAULT NULL")
```

### 2.2 存储格式规范

| 来源类型 | `connectionId` | `filePath` 格式 | 示例 |
|---------|---------------|----------------|------|
| 本地文件 | `null` | 绝对路径 / `content://` URI | `/storage/emulated/0/Movies/a.mp4` |
| 网络文件 | `连接ID` | `NetworkPlaybackUri` | `network://3/movies/a.mp4` |

**为什么不存原始 HTTP URL？**
- `NetworkPlaybackUri` 内嵌 `connectionId`，播放器可通过 `NetworkStreamingProxy` 自动处理认证
- 连接配置变更（密码、端口）后，URI 无需修改
- 与现有网络播放体系 100% 兼容

### 3.2 播放列表详情页加载流程

```
PlaylistDetailViewModel.observePlaylistItems()
  │
  ▼
playlistRepository.observePlaylistItems(playlistId)
  │
  ▼
对每个 PlaylistItemEntity 构建 PlaylistVideoItem：
  │
  ├── connectionId == null ──→ 本地文件分支（现有逻辑）
  │                              ├── content:// / file:// → resolveUri
  │                              └── 普通路径 → File(path) → MediaFileRepository
  │
  └── connectionId != null ──→ 网络文件分支（新增）
     │
     ├── 轻量可用性判断（不触发网络请求）
     │    ├── connection == null（连接被删） → isAvailable = false, reason = "连接已删除"
     │    └── connection != null            → isAvailable = true（不深探测）
     │
     ├── 构建 Video 对象
     │    ├── path = item.filePath（network://...）
     │    ├── uri = Uri.parse(path)
     │    ├── title/fileName = item.fileName
     │    ├── duration/size = 如有缓存则显示，否则 "--"
     │    └── bucketDisplayName = connection.name
     │
     └── 缩略图加载（交给 ThumbnailRepository）
          ├── 内存/磁盘缓存命中 → 正常显示
          └── 未缓存           → 显示默认占位图
```

### 3.3 可用性检测策略

**核心原则：懒检测，不阻塞列表加载**

| 阶段 | 检测深度 | 说明 |
|------|---------|------|
| 列表加载 | 轻量 | 仅检查 `connectionId` 对应的连接配置是否存在（查 DB，不联网） |
| 点击播放 | 深度 | 尝试建立连接/播放，失败时给出具体错误提示 |

```kotlin
// 列表加载时的轻量判断（PlaylistDetailViewModel）
fun checkAvailability(item: PlaylistItemEntity): AvailabilityState {
  if (item.connectionId == null) {
    // 本地文件：检查文件是否存在
    return if (File(item.filePath).exists()) Available else Unavailable("文件不存在")
  }
  
  // 网络文件：只查配置是否存在
  val connection = networkRepository.getConnectionById(item.connectionId)
  return if (connection == null) {
    Unavailable("连接配置已被删除")
  } else {
    // 不深探测服务器是否可达，避免阻塞
    Available
  }
}
```

### 3.4 播放流程（网络文件）

```
用户点击可用网络视频
  │
  ▼
launchPlaylistPlayback(item, index)
  │
  ▼
验证可用性（二次确认）
  │  如不可用 → Snackbar 提示，终止播放
  ▼
构建 PlaybackItem
  │  uri = NetworkPlaybackUri.create(connectionId, path)
  ▼
PreparedPlaybackLaunchStore.stage(queueItems, currentIndex)
  ▼
Intent → PlayerActivity
  │  data = network://3/movies/a.mp4
  │  extras: network_connection_id = 3
  │          network_file_path = movies/a.mp4
  ▼
PlayerActivity 解析 Intent
  │
  ▼
NetworkPlaybackUri.parse(uri) → 提取 connectionId + path
  │
  ▼
PlaybackSession 加载
  │
  ▼
mpv 请求播放 network://... URI
  │
  ▼
NetworkStreamingProxy 拦截请求
  │  查找/创建对应连接的客户端
  │  通过 WebDAV/SMB/FTP 客户端读取文件流
  │  代理为本地 HTTP 流供 mpv 播放
  ▼
正常播放
```

### 4.3 播放列表详情页 VideoCard 可用性适配

```kotlin
// PlaylistDetailScreen 中渲染 VideoCard 时
videoItems.forEachIndexed { index, item ->
  val isUnavailable = !item.isAvailable
  
  VideoCard(
    video = item.video,
    isSelected = selectionManager.isSelected(item.video),
    onClick = {
      if (isUnavailable) {
        showUnavailableSnackbar(item)
      } else {
        launchPlaylistPlayback(item, index)
      }
    },
    // 极 subtle 的离线标识：仅降低饱和度或不处理
    // 不降低整体 alpha，保持列表完整性
  )
}
```

**可选的 subtle 标识方案（择一实现）：**

| 方案 | 实现方式 | 视觉影响 |
|------|---------|---------|
| A. 无标识 | 不做任何特殊处理 | 零影响 |
| B. 小圆点 | 缩略图右下角 8dp 灰色圆点 | 极 subtle |
| C. CloudOff 图标 | 标题行末尾小图标 | 轻微提示 |
| D. 饱和度降低 | `Modifier.graphicsLayer { saturation = 0.6f }` | 轻微褪色 |

**推荐方案 A 或 B**：用户不主动点击几乎感知不到差异。

### 4.4 不可用提示 Snackbar

```kotlin
@Composable
private fun UnavailableSnackbarHost(
  item: PlaylistVideoItem,
  onDismiss: () -> Unit,
  onRemove: () -> Unit,
) {
  val message = buildString {
    append("「${item.video.displayName}」")
    append(
      when (item.availabilityReason) {
        "连接配置已被删除" -> "所在连接配置已被删除"
        "认证失败" -> "认证失败，请检查连接设置"
        else -> "所在连接当前不可用"
      }
    )
  }
  
  Snackbar(
    action = {
      TextButton(onClick = onRemove) {
        Text("移除")
      }
    },
    dismissAction = {
      IconButton(onClick = onDismiss) {
        Icon(Icons.RoundedFilled.Close, contentDescription = "Dismiss")
      }
    },
  ) {
    Text(message)
  }
}
```

## 7. 缩略图缓存机制详解

### 7.1 缓存层级

```
┌─────────────────────────────────────────┐
│           缩略图请求（VideoCard）          │
└─────────────────┬───────────────────────┘
                  │
    ┌─────────────┼─────────────┐
    ▼             ▼             ▼
┌────────┐   ┌────────┐   ┌─────────────┐
│内存缓存 │   │磁盘缓存 │   │ 网络提取     │
│LruCache│   │App缓存 │   │（需连接在线） │
└────┬───┘   └───┬────┘   └──────┬──────┘
     │           │               │
     │ 命中      │ 命中          │ 未命中
     ▼           ▼               ▼
  直接返回    读入内存          通过代理获取
  最快        后返回            文件流并提取帧
                                  │
                                  ▼
                              写入磁盘+内存
```

### 7.2 断连后的缩略图行为

| 缓存状态 | 行为 | 视觉效果 |
|---------|------|---------|
| 内存+磁盘均有 | 直接读取缓存，零网络请求 | 正常显示缩略图 |
| 仅磁盘有 | 读磁盘入内存后显示 | 正常显示缩略图 |
| 均无 | 无法生成（因无连接），返回 `null` | 显示默认占位图（灰色背景+图标） |

**关键保证**：断连后，`ThumbnailRepository.getCachedThumbnail()` 和 `getThumbnailFromMemory()` **不触发任何网络 I/O**，仅查询本地缓存。

## 8. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 数据库 Migration 出错 | 应用崩溃/数据丢失 | 充分测试 Migration；保留降级方案 |
| `NetworkPlaybackUri` 格式变更 | 播放失败 | 该格式已稳定使用于整个网络播放体系，风险极低 |
| 大量网络文件导致列表加载慢 | 用户体验差 | 懒检测策略避免网络探测；缩略图走缓存 |
| 用户误删连接后困惑 | 不理解为何条目还在 | Snackbar 明确提示原因 + 提供移除入口 |
| 本地/网络混合列表排序混乱 | 体验不一致 | `bucketDisplayName` 统一显示来源名称 |
