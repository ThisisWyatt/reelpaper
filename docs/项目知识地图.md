## 二、核心设计决策汇总

以下决策均可在源码中找到直接证据，文档中已标注来源。

| 决策 | 为什么这么设计 | 关键证据文件 |
|------|--------------|-------------|
| **进程级播放核心（PlaybackSession为object单例）** | Activity/Service均不拥有原生核心，旋转/PiP/后台仅做Surface绑定/解绑，避免核心反复创建销毁 | `PlaybackSession.kt` 源码注释："none of them owns the native core" |
| **MediaStore为真相源，拒绝启动时递归扫描根目录** | 避免大媒体库下的存储唤醒与重复工作，减少冷启动I/O | `App.kt` 源码注释 |
| **Surface丢失时挂起视频轨道（仅MediaCodec）** | MediaCodec硬件解码器绑定到特定ANativeWindow，Surface消失前必须停止解码，否则崩溃 | `PlaybackSession.kt:suspendVideoTrackForSurfaceLossLocked()` |
| **Generation代际机制** | 防止旧文件的回调事件污染新文件状态，实现命令过滤与位置恢复标记 | `PlaybackSession.kt` 中 `AtomicLong` 序列号 |
| **三级扫描策略（MediaStore→文件系统→元数据提取）** | 平衡查询性能与准确性：MediaStore毫秒级但.ts时长不可靠，文件系统验证做fallback | `VideoScanUtils.kt` |
| **本地代理架构（NanoHTTPD+Capability Token）** | 凭证隔离：URI中绝不包含密码；支持Range请求；可处理HLS sibling路径 | `NetworkStreamingProxy.kt`、`NetworkPlaybackUri.kt` |
| **网络密码AES-256-GCM+Keystore** | 硬件级密钥保护，明文自动迁移，防止日志泄露 | `NetworkCredentialCipher.kt`、`NetworkRepository.kt` |
| **Anime4K Shader移动端优化（FP16/mediump+C.R.E.L.U.）** | 移动GPU驱动差异大（部分Adreno忽略默认精度头），需显式注入精度限定符；减少纹理读取次数 | `Anime4KManager.kt` |
| **热感知性能降级（ThermalMonitor→Anime4K降级/Ambient采样预算）** | 高温时主动降低GPU负载，避免系统强制降频导致卡顿 | `ThermalMonitor.kt`、`Anime4KPlayback.kt` |
| **缩略图Smart模式多位置回退（33%→10s→20s→30s）** | 短视频或黑屏片头时，单一位置可能提取全黑帧，多位置尝试确保质量 | `ThumbnailRepository.kt` |
| **SkipMarkerResolver设计为无状态纯函数** | 与Android/mpv生命周期解耦，便于单元测试；PlayerViewModel负责组合事件流 | `SkipMarkerResolver.kt` |
| **Theme切换Telegram风格径向揭示动画** | 捕获当前位图→径向渐变蒙版揭示新主题，提供流畅的视觉连续性 | `Theme.kt:ThemeTransitionState` |
| **Deferred初始化（缩略图预热/元数据维护延迟到首次Activity后）** | 避免冷启动时与首帧竞争资源 | `App.kt:scheduleFastThumbnailWarmupOnce()` |
| **空闲libmpv核心3分钟自动回收** | 释放原生解码器/渲染器资源，同时保留足够复用窗口 | `App.kt:startIdleMpvCoreReaper()` |
| **Koin全单例、无作用域分层** | ViewModel/Activity级短生命周期对象由Compose/Architecture Components自行管理，DI容器只管应用级长生命周期服务 | `di/*.kt` 中全部 `single` 声明 |
| **播放状态保存的并发安全（mediaIdentifier vs activeSaveMediaIdentifier）** | 防止播放切换窗口期将旧视频位置保存到新视频的Room记录中 | `PlayerActivity.kt` 中 `@Volatile` 字段 |
