## 1. 模块概述

章节与跳过标记模块负责以下功能：

1. **章节导航**：从 mpv 播放核心读取视频章节列表，在播放器 UI 中展示章节标记与章节列表，并支持点击跳转。
2. **片头/片尾/预览跳过**：通过两种途径生成"跳过段"（Skip Segment）：
   - **本地章节关键词检测**：分析视频章节名称中的关键词（如 "Opening"、"Ending"），自动识别片头/片尾/前情提要/预告等区间。
   - **在线提供商查询**：向第三方服务（IntroDB、TIDB、AniSkip、AnimeSkip）查询片头/片尾时间戳。
3. **自动跳过**：当播放进度进入跳过段区间时，可选择自动 seek 到段尾，或显示可点击的跳过芯片（Skip Chip）供用户手动跳过。
4. **进度条可视化**：在 seekbar 上以间隙形式标示章节边界，并以半透明彩色遮罩标示跳过段范围。
5. **SponsorBlock（yt-dlp）**：在 yt-dlp 网络播放场景下，通过 yt-dlp 原生参数透传 SponsorBlock 配置，由 yt-dlp 在服务端/提取阶段处理赞助片段跳过。

data class SkipSegment(

## 4. 跳过标记解析引擎

### 4.1 SkipMarkerResolver

文件：`app/src/main/java/app/gyrolet/mpvrx/ui/player/SkipMarkerResolver.kt`

`SkipMarkerResolver` 是一个**独立的无状态对象**，负责所有跳过标记的解析、分类、合并与目标 seek 计算，与 mpv/Android 生命周期解耦。

#### 4.1.1 章节标题分类（`classifyTitle`）

```kotlin
fun classifyTitle(
  title: String?,
  introKeywords: List<String>,
  outroKeywords: List<String>,
  recapKeywords: List<String>,
  creditsKeywords: List<String>,
  previewKeywords: List<String>,
): SkipSegmentType?
```

- 对标题进行多维度归一化：`lowercase(Locale.ROOT)` → 去除非拉丁字符的空格归一化 → 紧凑拉丁形式 → 紧凑原始形式（保留日文等字符）。
- 关键词匹配策略：
  - 纯字母数字关键词（长度 ≥ 4）：支持词边界匹配（`(?:^|\s)keyword(?:\s|$)`）或紧凑包含匹配。
  - 非纯字母数字关键词（如日文）：去除空格/标点后在紧凑原始字符串中直接包含匹配。
- 优先级（由高到低）：`RECAP` > `CREDITS` > `PREVIEW` > `OUTRO`（且不同时匹配 INTRO）> `INTRO`。

#### 4.1.2 章节到跳过段的解析（`resolveChapters`）

```kotlin
fun resolveChapters(
  chapters: List<ChapterSkipMarker>,
  durationSeconds: Double,
  classify: (String?) -> SkipSegmentType?,
): List<SkipSegment>
```

- 过滤掉不在 `[0, duration)` 范围内的章节。
- 对每个章节调用 `classify`；若分类成功，则该段的结束时间取**下一章节的开始时间**（若无则取视频总时长），上限不超过 `durationSeconds`。
- 返回的段 `source` 固定为 `"chapter"`。

#### 4.1.3 提供商段解析（`resolveProviderSegment` / `resolveProviderSegments`）

- `resolveProviderSegment`：将提供商返回的 `segmentType`、`startSeconds`、`endSeconds` 映射为 `SkipSegment`。
  - 类型映射规则：
    - `"recap"` / `"summary"` → `RECAP`
    - `"credit"` → `CREDITS`
    - `"preview"` / `"next"` → `PREVIEW`
    - `"out"` / `"ending"` / `"ed"` / `"mixed-ed"` → `OUTRO`
    - 其余 → `INTRO`
  - 若 `endSeconds` 缺失，则取 `durationSeconds` 或同一下一段的 `startSeconds`。
- `resolveProviderSegments`：对一批提供商标记排序后逐段解析，并自动用「下一段的起始时间」补全缺失的结束时间。

#### 4.1.4 合并与去重（`merge`）

```kotlin
fun merge(segments: Iterable<SkipSegment>): List<SkipSegment>
```

- 先过滤无效段（非有限值、负值、end ≤ start）。
- 排序规则：先按 `startSeconds`，再按 `endSeconds`，再按 `type.ordinal`。
- 去重容差：`DUPLICATE_TOLERANCE_SECONDS = 0.001` 秒。若两段类型相同且起止时间都在容差内，则视为重复，仅保留一条。

#### 4.1.5 Seek 目标计算（`seekTarget`）

```kotlin
fun seekTarget(segment: SkipSegment, durationSeconds: Double): Double
```

- 常规情况直接返回 `segment.endSeconds`。
- 若 `endSeconds` 恰好等于视频总时长，为避免 seek 到 mpv 的精确 EOF 导致异常，采用保护策略：
  - 目标设为 `durationSeconds - EOF_SEEK_GUARD_SECONDS`（`0.25` 秒）。
  - 若该值仍大于 `startSeconds`，则使用它；否则取段中点。

### 6.2 提供商查询层（IntroDbRepository）

文件：`app/src/main/java/app/gyrolet/mpvrx/repository/IntroDbRepository.kt`

`IntroDbRepository` 通过 OkHttp 向各提供商发起 HTTP 请求，核心方法为 `lookupSegments(request: IntroDbLookupRequest): IntroDbLookupOutcome`。

#### 6.2.1 IntroDB App (`api.introdb.app`)

- 请求地址：`https://api.introdb.app/segments?imdb_id={imdbId}&season={season}&episode={episode}`
- 需要 IMDb ID，支持季/集参数。
- 返回 JSON 数组，直接反序列化为 `List<IntroDbSegment>`。

#### 6.2.2 TheIntroDB / TIDB (`api.theintrodb.org`)

- 请求地址：
  - v2: `https://api.theintrodb.org/v2/media?tmdb_id={tmdbId}&season={season}&episode={episode}`
  - v1: `https://api.theintrodb.org/v1/media`（v2 返回 404 时的 fallback）
- 支持 TMDB ID 或 IMDb ID。
- 对 404 回退到 v1；其余非成功状态码视为错误。

#### 6.2.3 AniSkip (`api.aniskip.com`)

- 请求地址：`https://api.aniskip.com/v1/skip-times/{malId}/{episode}?types=op&types=ed&types=mixed-op&types=mixed-ed&types=recap&types=preview&episodeLength=0`
- 需要 MyAnimeList (MAL) ID 和集数。
- 返回体中的 `skipType` 映射规则：`op`/`opening` → `opening`，`ed`/`ending` → `ending`，`recap` → `recap`，`preview` → `preview`。
- 若 MAL ID 未直接提供，则通过 Jikan API (`api.jikan.moe/v4/anime`) 以标题搜索获取。

#### 6.2.4 AnimeSkip (`api.anime-skip.com/graphql`)

- 使用 GraphQL 查询：`searchShows(search: ..., limit: 3)`，返回剧集及其 `timestamps`。
- 需附带请求头 `X-Client-ID: ZGfO0sMF3eCwLYf8yMSCJjlynwNGRXWE`。
- 对返回的 `timestamps` 列表按时间排序，相邻两个时间戳之间构成一个段（当前时间戳为 start，下一个为 end）。
- 类型映射：`recap`/`summary` → `recap`，`opening`/`intro`/`op` → `opening`，`ending`/`outro`/`credit`/`ed` → `ending`，`preview`/`next` → `preview`。

#### 6.2.5 标题解析与 ID 提取

- `MediaInfoParser.parse(titleForLookup)` 提取规范化标题、季、集、年份、媒体类型。
- IMDb ID 提取：正则 `tt\d{7,9}`，从 `mediaTitle`、`lookupHint`、`canonicalTitle` 中扫描。
- MAL ID 提取：从 `myanimelist.net/anime/(\d+)` URL 或直接匹配 `\d{3,8}` 数字串。

#### 6.2.6 TMDB 搜索（用于 IntroDB / TIDB 无直接 ID 时）

- 搜索接口：`https://sub.wyzie.io/api/tmdb/search?q={title}`
- 评分维度：媒体类型匹配 (+30)、年份匹配 (+25)、标题精确/前缀/包含匹配 (+80/+45/+20)。
- 最低得分阈值：20 分。

#### 6.2.7 Jikan / MAL 搜索与匹配评分（用于 AniSkip / AnimeSkip）

- 搜索接口：`https://api.jikan.moe/v4/anime?q={query}&limit=10`
- 候选查询词：规范化标题，若季数 > 1 则额外构造 `"{title} Season {n}"` 和 `"{title} {ordinal} Season"`。
- 最多取前 4 个候选词搜索，结果去重聚合。
- 评分规则（`buildAniSkipScore`）：
  - 标题匹配（精确 120 / 前缀 92 / 包含 70 / 词重叠 12×）
  - 类型为 TV (+10)
  - 含惩罚词（`recap`/`summary`/`digest`/`compilation`）(-45)
  - 季数匹配：标题中检测到预期季号 (+55)，未检测到且预期季 > 1 (-15)，检测到但不匹配 (-70)
- 最低通过阈值：`ANISKIP_MATCH_THRESHOLD = 60`。

### 6.3 Hybrid 提供商策略

文件：`app/src/main/java/app/gyrolet/mpvrx/ui/player/PlayerViewModel.kt`（第 3636–3696 行）

- 当用户选择 `HYBRID` 时，`PlayerViewModel` 使用 `async(Dispatchers.IO) { ... }.awaitAll()` 并发查询四个提供商：IntroDB、TIDB、AniSkip、AnimeSkip。

### 7.2 自动跳过检测

```kotlin
private fun maybeAutoSkipIntro(positionSeconds: Double) {
  val activeSegment = skipSegmentsSnapshot.firstOrNull { segment ->
    positionSeconds >= segment.startSeconds &&
      positionSeconds < segment.endSeconds &&
      segment !in skippedSegments
  }
  ...
  if (paused == true || activeSegment == null) return
  val autoSkipEnabled = when (activeSegment.type) {
    SkipSegmentType.INTRO -> playerPreferences.autoSkipIntro.get()
    SkipSegmentType.RECAP -> playerPreferences.autoSkipIntro.get()
    SkipSegmentType.OUTRO -> playerPreferences.autoSkipOutro.get()
    SkipSegmentType.CREDITS -> playerPreferences.autoSkipOutro.get()
    SkipSegmentType.PREVIEW -> playerPreferences.autoSkipOutro.get()
  }
  if (!autoSkipEnabled) return
  skippedSegments += activeSegment
  _showSkipChipAuto.value = false
  seekPastSkipSegment(activeSegment, auto = true)
}
```

- 触发时机：在播放位置更新回调中逐帧调用（与 mpv 的 `time-pos` 同步）。

- 映射规则：
  - `INTRO` / `RECAP` → 受 `autoSkipIntro` 控制
  - `OUTRO` / `CREDITS` / `PREVIEW` → 受 `autoSkipOutro` 控制

- 用户点击跳过芯片后调用，将当前段标记为已跳过并 seek。

### 7.5 Seek 与 Syncplay 同步

```kotlin
private fun seekPastSkipSegment(segment: SkipSegment, auto: Boolean) {
  val seekTarget = SkipMarkerResolver.seekTarget(segment, currentDurationSeconds())
  PlaybackSession.setPropertyDouble("time-pos", seekTarget)
  syncplayManager.updatePlayerState(seekTarget, ..., doSeek = true)
  showToast(if (auto) "${segment.label} (auto)" else segment.label)
}
```

- 通过 `PlaybackSession.setPropertyDouble("time-pos", ...)` 直接设置 mpv 播放位置。
- 若用户启用了 Syncplay，则同步向 Syncplay 服务器广播 seek 事件。
- 显示 Toast 提示用户已跳过（自动跳过带 `"(auto)"` 后缀）。

## 12. 架构要点总结

1. **数据来源分层**：
   - 本地章节数据来自 mpv 核心属性 `chapter-list`。
   - 在线标记数据来自四个独立 REST/GraphQL API，由 `IntroDbRepository` 统一管理。
   - 两类数据最终都转化为统一的 `SkipSegment`，通过 `SkipMarkerResolver.merge()` 合并去重。

2. **性能优化**：
   - `skipSegmentsSnapshot` 使用 `@Volatile` 本地变量，避免在逐帧回调中订阅 StateFlow。
   - Seekbar 上的 `SkipSegmentOverlay` 和 `chapterFractions` 均使用 `remember` 缓存，减少高频重绘时的对象分配。
   - 在线查询结果通过 `SharedPreferences` + JSON 序列化进行磁盘缓存，并设有 TTL 和容量上限。

3. **生命周期隔离**：
   - `SkipMarkerResolver` 是纯函数对象，不依赖 Android 生命周期或 mpv 状态，便于单元测试。
   - `PlayerViewModel` 负责将 mpv 事件流、偏好变化流、网络协程三者组合，统一输出为 `skipSegments` / `currentSkippableSegment` / `showSkipChipAuto` 三个 UI 状态流。

4. **多语言支持**：
   - 默认关键词库内置了日语片假名/汉字关键词（如 `オープニング`、`エンディング`、`次回予告` 等）。
   - `classifyTitle` 的匹配逻辑同时支持拉丁字符的词边界匹配和非拉丁字符的紧凑包含匹配。
