## 1. 架构哲学：进程级单例核心

mpvRx 的播放架构遵循一个核心设计原则：**libmpv 原生核心是进程级单例，不被任何 Activity 或 Service 拥有**。

这意味着：
- **没有 Activity 拥有播放器**：`PlayerActivity` 不创建/销毁 libmpv，只绑定/解绑 Surface
- **旋转是 Surface 切换**：配置变更时，旧 Activity 解绑 Surface，新 Activity 绑定同一 Surface
- **PiP 是 Surface 共享**：画中画窗口与主播放器共享同一媒体会话
- **后台播放是 Surface 解绑**：进入后台时仅解绑 Surface 并暂停视频解码，音频继续
- **通知栏重入是 Activity 重建**：点击通知返回时创建新的 `PlayerActivity` 实例，但核心已存在

## 2. PlaybackSession — 进程级状态机

### 2.1 状态定义

```kotlin
data class PlaybackSessionState(
  val phase: PlaybackPhase = PlaybackPhase.UNINITIALIZED,
  val generation: Long = 0L,           // 当前媒体代际
  val activeGeneration: Long = 0L,     // 已确认加载的代际
  val surfaceAttached: Boolean = false,
  val paused: Boolean = true,
  val currentItem: PlaybackItem? = null,
  val error: String? = null,
)
```

### 2.2 播放阶段（PlaybackPhase）

```
UNINITIALIZED ──→ INITIALIZING ──→ IDLE ──→ LOADING ──→ READY
                                              │    ▲       │
                                              │    │       │
                                              ▼    │       ▼
                                            ERROR  │     BACKGROUND
                                                   │
                                            STOPPING ──→ IDLE
```

| 阶段 | 含义 | 触发条件 |
|------|------|---------|
| `UNINITIALIZED` | 核心未创建 | 应用启动后首次使用前的初始状态 |
| `INITIALIZING` | 核心创建中 | `PlaybackSession.initialize()` 调用后 |
| `IDLE` | 核心就绪，无媒体 | 初始化完成、停止完成、播放结束 |
| `LOADING` | 媒体加载中 | `loadfile` 命令发送后至 `FILE_LOADED` 事件 |
| `READY` | 媒体可播放 | `FILE_LOADED` 且位置恢复完成 |
| `BACKGROUND` | 后台音频播放 | Surface 解绑后，从 READY 降级 |
| `STOPPING` | 停止中 | `stop` 命令发送后至 `END_FILE` 事件 |
| `ERROR` | 加载失败 | `END_FILE` 原因 ERROR，或超时 |

### 2.3 Generation（代际）机制

每次加载新文件时，`generation` 原子递增（`AtomicLong` 序列号）。代际用于：

1. **防止竞态**：旧文件的回调事件不会污染新文件的状态
2. **命令过滤**：`commandForGeneration(expectedGeneration, ...)` 仅对当前代际生效
3. **位置恢复标记**：`pendingPositionRestoreGeneration`、`initialPositionGeneration` 绑定到特定代际
4. **网络流生命周期**：`activeNetworkStream` 的注册与代际解耦，但由 stop/load 事件驱动释放

```kotlin
val generation = _state.value.generation + 1L
updateState { it.copy(phase = PlaybackPhase.LOADING, generation = generation, ...) }
MPVLib.command("loadfile", playableUri, "replace", "-1", loadOptions)
```

### 2.4 核心初始化流程

```kotlin
fun initialize(context, configDir, cacheDir, coreConfigurationKey, initOptions, postInitOptions, observeProperties): Result<Boolean> {
  nativeLock.withLock {
    if (initialized && activeCoreConfigurationKey == coreConfigurationKey) return false
    if (initialized) destroyLocked()  // 配置变更时重建核心

    MPVLib.create(context)
    MPVLib.setOptionString("config", "yes")
    MPVLib.setOptionString("config-dir", configDir)
    MPVLib.setOptionString("gpu-shader-cache-dir", cacheDir)
    MPVLib.setOptionString("icc-cache-dir", cacheDir)

    initOptions()          // 应用启动前配置（优先级高于 mpv.conf）
    MPVLib.init()          // 解析 mpv.conf，创建核心
    nativeCoreReady = true

    defaultUserAgent = MPVLib.getPropertyString("user-agent")
    postInitOptions()      // 初始化后配置
    MPVLib.setOptionString("force-window", "no")
    MPVLib.setOptionString("idle", "yes")
    MPVLib.addObserver(this)
    reobserveTrackedProperties()
    observeProperties()
    initialized = true
  }
}
```

### 2.5 Surface 绑定机制

```kotlin
fun bindSurface(surface, width, height, owner, ownerIsActive): Boolean {
  withCore(default = false) {
    // 1. 如果 Surface 已绑定给其他 owner，先解绑
    if (_state.value.surfaceAttached && attachedSurfaceOwner !== owner) {
      detachRendererSurfaceLocked()
    }
    // 2. 附加新 Surface
    MPVLib.attachSurface(surface)
    MPVLib.setOptionString("force-window", "yes")
    MPVLib.setPropertyString("vo", desiredVideoOutput)  // 通常为 "gpu"
    attachedSurfaceOwner = owner
    updateState { it.copy(surfaceAttached = true) }
    // 3. 恢复之前挂起的视频轨道
    restoreSuspendedVideoTrackLocked()
    // 4. 处理延迟视频选择
    if (deferredVideoSelectionGeneration == _state.value.generation) {
      MPVLib.setPropertyString("vid", "auto")
      deferredVideoSelectionGeneration = null
    }
  }
}
```

**Surface 解绑**（`unbindSurface`）：
- 若处于 `LOADING` 阶段：延迟视频选择（`deferredVideoSelectionGeneration = generation`）
- 若处于 `READY`/`BACKGROUND`：挂起视频轨道（`suspendVideoTrackForSurfaceLossLocked`）
- 统一执行：`vo=null`、`force-window=no`、`detachSurface()`

### 2.6 视频轨道挂起与恢复（硬件解码器兼容）

```kotlin
private fun suspendVideoTrackForSurfaceLossLocked() {
  val activeHardwareDecoder = MPVLib.getPropertyString("hwdec-current").orEmpty()
  if (!activeHardwareDecoder.contains("mediacodec", ignoreCase = true)) return
  val activeVid = MPVLib.getPropertyInt("vid") ?: -1
  if (activeVid > 0) {
    suspendedVideoTrack = SuspendedVideoTrack(activeVid, current.generation)
    MPVLib.setPropertyString("vid", "no")  // 停止视频解码，保持音频
  }
}
```

**设计意图**：MediaCodec 硬件解码器绑定到特定 `ANativeWindow`，Surface 消失前必须停止解码，否则可能崩溃。

## 3. PlayerActivity 生命周期与播放交互

### 3.1 Activity 启动模式

```xml
<activity
  android:name=".ui.player.PlayerActivity"
  android:launchMode="singleTask"
  android:supportsPictureInPicture="true"
  ... />
```

- **`singleTask`**：确保只有一个播放器实例。新文件通过 `onNewIntent` 传入
- **`supportsPictureInPicture`**：支持系统级 PiP

### 3.2 启动流程

```
onCreate()
    │
    ├──→ 初始化 ViewModel、Binding、Preferences 注入
    ├──→ 判断 isSecureFolderLaunch（安全文件夹模式）
    ├──→ 处理 Intent（onNewIntent 逻辑也走这里）
    │       ├──→ EXTRA_PREPARED_PLAYBACK_TOKEN → PreparedPlaybackLaunchStore.retrieve()
    │       ├──→ 普通文件 URI → 创建 PlaybackItem
    │       └──→ 网络流 → 构建 networkPlaylist 元数据
    │
    ├──→ PlaybackSession.initialize()（若核心未就绪）
    ├──→ PlaybackSession.bindSurface(player.holder.surface, owner = this)
    ├──→ 注册 PlayerObserver
    ├──→ 请求音频焦点
    └──→ 设置 MediaSession 回调

onResume()
    │
    ├──→ markForeground() → PlaybackSession.markForeground()
    ├──→ MediaPlaybackService.activityForeground = true
    └──→ 恢复系统 UI（沉浸式模式）

onPause()
    │
    ├──→ 保存播放状态到 Room
    ├──→ markBackground() → PlaybackSession.markBackground()
    └──→ 启动后台服务（若启用后台播放）

onStop()
    │
    └──→ 保存播放状态（双重保险）

onDestroy()
    │
    ├──→ 解绑 Surface（若仍绑定）
    ├──→ 移除 PlayerObserver
    └──→ 决定是否停止服务/核心（取决于后台播放设置）
```

### 3.3 Secure Folder 模式

```kotlin
private var isSecureFolderLaunch = false
```

- 从安全文件夹启动的播放会话**永不进入最近任务/播放历史**
- 由于 `singleTask`，`onNewIntent` 可能复用同一 Activity 实例
- `isSecureFolderLaunch` 在 `onCreate` 和 `onNewIntent` 中重新计算，不是 `by lazy`

### 3.4 播放状态保存的并发安全

```kotlin
@Volatile
private var activeSaveMediaIdentifier: String = ""
```

- `mediaIdentifier`：当前 Intent 中的媒体标识（切换播放项时立即更新）
- `activeSaveMediaIdentifier`：实际已加载完成的媒体标识（在 `handleFileLoaded` 中更新）
- **目的**：防止在播放切换窗口期，将旧视频的位置保存到新视频的 Room 记录中

## 4. MediaPlaybackService — 后台播放与 MediaSession

### 4.1 服务定位

`MediaPlaybackService` 是一个 `LifecycleService`（或标准 `Service`），负责：
1. **前台通知**：显示播放控制通知，保持进程存活
2. **MediaSession**：向系统暴露播放状态，支持蓝牙、Android Auto、锁屏控制
3. **音频焦点管理**：处理来电、导航等音频抢占
4. **后台进度保存**：定时将播放位置写入 Room
5. **音频后台播放**：Activity 销毁后，若启用音频后台，继续播放

### 4.2 Activity ↔ Service 协作模型

```
┌─────────────────┐                    ┌─────────────────────┐
│  PlayerActivity  │                    │ MediaPlaybackService │
│                 │                    │                     │
│  activityForeground│                 │  mpvAccessReleased  │
│     = true       │──────────────────→│     = false         │
│                 │  (通过 companion   │                     │
│  绑定 Surface   │   对象方法)        │  持有音频焦点       │
│  不持有音频焦点 │◄───────────────────│  发布通知           │
│                 │                    │                     │
│  onDestroy()    │                    │  若音频后台启用：   │
│  (用户划掉)      │                    │  继续播放 / 否则停止 │
└─────────────────┘                    └─────────────────────┘
```

**关键方法**（Companion Object）：

```kotlin
companion object {
  var activityForeground = false
    set(value) {
      field = value
      if (value) {
        service.handingBackToActivity = true
        service.abandonAudioOwnership()  // Activity 接管音频焦点
      }
    }

  internal fun prepareForActivityHandoff() {
    // 通知栏点击返回 Activity 时，Service 立即释放焦点
  }

  internal fun prepareForMpvShutdown() {
    // Activity 销毁核心前，Service 释放所有 MPV 访问
  }
}
```

### 4.3 音频焦点状态机

```kotlin
@Volatile private var ownsAudioFocus = false
@Volatile private var hasAudioFocus = false
@Volatile private var resumeAfterFocusGain = false
@Volatile private var volumeBeforeDuck: Double? = null
```

| 焦点事件 | 行为 |
|---------|------|
| `AUDIOFOCUS_LOSS` | 永久失去焦点：暂停播放、放弃所有权 |
| `AUDIOFOCUS_LOSS_TRANSIENT` | 临时失去：暂停、标记恢复意图 |
| `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK` | 可降音量：音量降至 50% |
| `AUDIOFOCUS_GAIN` | 重新获得：恢复音量、若之前暂停则恢复播放 |

### 4.4 通知与队列

Service 维护：
- `mediaTitle`、`mediaArtist`、`mediaUri`
- `paused`、`playbackSpeed`
- `chapters`、`currentChapterIndex`
- `activeQueueItemId`、`publishedQueueIndexes`

通知意图通过 `PendingIntent` 指向 `PlayerActivity`，携带 `EXTRA_PREPARED_PLAYBACK_TOKEN` 用于恢复播放状态。

## 5. 音频保护机制

### 5.1 Seek 音频保护（Seek Audio Guard）

**问题**：快速 seek 时，解码器刷新之间可能泄漏微小音频片段，产生回声/颤音。

**解决**：
```kotlin
private fun beginSeekAudioGuardLocked() {
  if (seekAudioGuardPreviousMute == null) {
    seekAudioGuardPreviousMute = MPVLib.getPropertyBoolean("mute") ?: false
    if (!wasMuted) MPVLib.setPropertyBoolean("mute", true)
  }
  seekAudioGuardToken++
  scheduleSeekAudioGuardRestoreLocked(SEEK_AUDIO_FALLBACK_RESTORE_MS)  // 750ms 兜底
}
```

- **触发**：每次 `seek` 命令
- **恢复**：`MPV_EVENT_PLAYBACK_RESTART` 事件后 60ms 延迟恢复
- **兜底**：750ms 强制恢复，防止事件丢失导致永久静音

### 5.2 播放过渡音频保护（Playback Transition Audio Guard）

**问题**：文件切换或停止时，AudioTrack 可能排空旧缓冲尾，产生杂音。

**解决**：
```kotlin
private fun beginPlaybackTransitionAudioGuardLocked(canRestore: Boolean) {
  playbackTransitionAudioGuardPreviousMute =
    seekAudioGuardPreviousMute ?: (MPVLib.getPropertyBoolean("mute") ?: false)
  MPVLib.setPropertyBoolean("mute", true)
  playbackTransitionAudioGuardCanRestore = canRestore
}
```

- **触发**：`loadfile` 前、`stop` 前
- **恢复**：`MPV_EVENT_PLAYBACK_RESTART` 后 180ms
- **不可恢复模式**：`canRestore = false`（停止时不恢复，直接静音）

### 5.3 两者关系

```
seek 命令
    │
    ▼
beginSeekAudioGuardLocked() ──→ mute = true
    │
    ├──→ MPV_EVENT_PLAYBACK_RESTART ──→ 60ms 后恢复 mute
    │
    └──→ 750ms 兜底超时 ──→ 强制恢复 mute

loadfile / stop
    │
    ▼
beginPlaybackTransitionAudioGuardLocked(canRestore)
    │
    ├──→ canRestore=true: MPV_EVENT_PLAYBACK_RESTART ──→ 180ms 后恢复
    │
    └──→ canRestore=false: 不恢复（用于终止播放）
```

**重叠处理**：若 seek guard 活跃时触发 transition guard，transition guard 会继承 seek guard 的原始 mute 状态，而非临时 mute 状态。

## 6. 属性观察系统

### 6.1 PlaybackProperty

```kotlin
class PlaybackProperty<T> internal constructor(
  internal val format: Int,
  private val reader: (String) -> T?,
) {
  private val states = ConcurrentHashMap<String, MutableStateFlow<T?>>()

  operator fun get(property: String): StateFlow<T?> {
    val candidate = MutableStateFlow<T?>(null)
    val existing = states.putIfAbsent(property, candidate)
    val state = existing ?: candidate
    if (existing == null) {
      PlaybackSession.observeProperty(property, format)
      state.value = reader(property)
    }
    return state.asStateFlow()
  }
}
```

### 6.2 预定义属性访问器

```kotlin
val propInt     = PlaybackProperty(MPV_FORMAT_INT64, ::getPropertyInt)
val propLong    = PlaybackProperty(MPV_FORMAT_INT64) { getPropertyInt(it)?.toLong() }
val propBoolean = PlaybackProperty(MPV_FORMAT_FLAG, ::getPropertyBoolean)
val propDouble  = PlaybackProperty(MPV_FORMAT_DOUBLE, ::getPropertyDouble)
val propFloat   = PlaybackProperty(MPV_FORMAT_DOUBLE, ::getPropertyFloat)
val propString  = PlaybackProperty(MPV_FORMAT_STRING, ::getPropertyString)
val propNode    = PlaybackProperty(MPV_FORMAT_NODE, ::getPropertyNode)
```

### 6.3 使用方式

```kotlin
// 在 ViewModel / Composable 中观察
val pauseState: StateFlow<Boolean?> = PlaybackSession.propBoolean["pause"]
val durationState: StateFlow<Double?> = PlaybackSession.propDouble["duration"]
```

**设计意图**：
- 懒加载：首次访问时才向 libmpv 注册属性观察
- 线程安全：`ConcurrentHashMap` + `CopyOnWriteArraySet` 保证多观察者安全
- 核心重建后自动重新观察：`reobserveTrackedProperties()`

## 7. 事件分发系统

### 7.1 事件处理优先级

`PlaybackSession` 自身实现 `MPVLib.EventObserver`，处理核心事件后再分发给外部观察者：

```kotlin
override fun event(eventId: Int, data: MPVNode) {
  val shouldForward = nativeLock.withLock {
    when (eventId) {
      MPV_EVENT_START_FILE -> { /* 更新 phase 为 LOADING */ true }
      MPV_EVENT_FILE_LOADED -> { /* 更新 phase 为 READY/BACKGROUND */ true }
      MPV_EVENT_PLAYBACK_RESTART -> { /* 恢复音频保护 */ true }
      MPV_EVENT_END_FILE -> { /* 处理停止/错误/EOF */ true }
      MPV_EVENT_SHUTDOWN -> { /* 全量清理 */ true }
      else -> true
    }
  }
  if (shouldForward) {
    observerSnapshot().forEach { observer -> observer.event(eventId, data) }
  }
}
```

### 7.2 END_FILE 事件处理

```kotlin
MPV_EVENT_END_FILE -> {
  val reason = parseEndFileReason(data)
  when {
    // 1. 被取代的停止事件（superseded stop）
    supersededStopGeneration != 0L && activeGeneration == 0L &&
      reason in {STOP, QUIT} -> { /* 忽略，不转发 */ }

    // 2. 正常停止流程
    current.phase == STOPPING -> {
      if (reason == REDIRECT) MPVLib.command("stop")
      else finalizeStopLocked()
    }

    // 3. 播放结束或错误
    current.activeGeneration == current.generation -> {
      if (reason == REDIRECT && loadedGeneration != generation) {
        updateState { activeGeneration = 0L }  // 保持 LOADING
      } else {
        val isFailure = reason == ERROR || (failedBeforeReady && reason !in {STOP, QUIT})
        updateState { phase = if (isFailure) ERROR else IDLE }
      }
    }
  }
}
```
