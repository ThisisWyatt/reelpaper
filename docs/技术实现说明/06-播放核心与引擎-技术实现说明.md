# 播放核心与引擎 — 技术实现说明

> 本文档深入分析 mpvRx 播放器项目中**播放核心与引擎**模块的源码实现。所有内容均来源于源码，具体文件路径与行号已标注。

---

## 一、概述

mpvRx 的播放核心基于 **libmpv** 原生库构建，通过 JNI 层 (`is.xyz.mpv.MPVLib`) 与 Android 层交互。整个播放状态由进程级单例 [`PlaybackSession`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L96) 统一管理，确保屏幕旋转、PiP、后台播放、通知栏重入等场景下核心实例的复用与稳定性。

渲染层由自定义的 [`MPVView`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L47)（继承自 `BaseMPVView`）负责 Surface 绑定与渲染后端配置。视频处理（滤镜、Anime4K、HDR）通过 mpv 的 GLSL shader 管线与选项系统实现。

---

## 二、解码与渲染

### 2.1 libmpv 引擎与 PlaybackSession 架构

[`PlaybackSession`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L96) 是一个 `object` 单例，作为**进程范围内唯一的 libmpv 播放状态所有者**。其设计要点如下：

- **核心复用**：Android 各屏幕（全屏播放器、迷你播放器、PiP）以及后台播放服务均通过观察/控制此对象，没有任何组件直接拥有原生核心。这使得旋转、PiP、后台播放等场景变为 Surface 的绑定/解绑操作，而非竞争性的创建/销毁循环（见 [`PlaybackSession.kt:88-94`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L88-L94)）。
- **生命周期管理**：核心创建走 [`initialize()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L230) 方法，销毁走 [`destroy()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L544)。初始化时通过 `coreConfigurationKey` 判断配置是否变化，若变化则销毁旧核心并重建（见 [`PlaybackSession.kt:241-246`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L241-L246)）。
- **Surface 绑定/解绑**：[`bindSurface()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L322) 和 [`unbindSurface()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L369) 专门处理 Android Surface 的生命周期。解绑时若处于 `LOADING` 阶段会延迟视频轨道选择（`deferredVideoSelectionGeneration`），避免丢弃已缓存的数据包（见 [`PlaybackSession.kt:372-378`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L372-L378)）。
- **视频轨道挂起**：当 Surface 丢失时，当前视频轨道 ID 被保存到 [`SuspendedVideoTrack`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L139) 中，待 Surface 恢复后自动还原（见 [`PlaybackSession.kt:348`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L348)）。
- **属性观察系统**：通过 [`PlaybackProperty`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L56) 类将 mpv 原生属性（`MPVLib.observeProperty`）桥接为 Kotlin `StateFlow`，支持多观察者（见 [`PlaybackSession.kt:221-227`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackSession.kt#L221-L227)）。

### 2.2 渲染后端选择

渲染后端的决策集中在 [`MPVView.selectRenderBackend()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L601) 中，受以下偏好影响：

- `gpu-next`（`DecoderPreferences.gpuNext`）
- Vulkan（`DecoderPreferences.useVulkan`）
- Anime4K 启用状态

选择优先级（见 [`MPVView.kt:688-752`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L688-L752)）：

| 条件 | 选择的 VO | GPU API | GPU Context |
|------|-----------|---------|-------------|
| Anime4K + gpu-next + 无 Vulkan | `gpu` | `opengl` | `android` |
| gpu-next + Vulkan | `gpu-next` | `vulkan` | `androidvk` |
| gpu-next（无 Vulkan） | `gpu-next` | `opengl` | `android` |
| Vulkan（无 gpu-next） | `gpu` | `vulkan` | `androidvk` |
| 默认 | `gpu` | `opengl` | `android` |

Vulkan 可用性由 [`RendererBackendPolicy.canUseVulkan()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/RendererBackendPolicy.kt#L13) 判定，需同时满足：构建包含 Vulkan、设备支持 Vulkan、用户启用 Vulkan、未强制 OpenGL 回退。

### 2.3 解码器模式

解码器偏好定义在 [`PlayerEnums.Decoder`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlayerEnums.kt#L78) 中：

| 枚举 | 显示名 | mpv `hwdec` 值 |
|------|--------|----------------|
| `AutoCopy` | Auto | `auto-copy` |
| `Auto` | Auto | `auto` |
| `SW` | SW | `no` |
| `HW` | HW | `mediacodec-copy` |
| `HWPlus` | HW+ | `mediacodec` |

实际写入 mpv 的 `hwdec` 值由 [`RendererBackendPolicy.preferredHwdecMode()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/RendererBackendPolicy.kt#L29) 决定：

- 若硬件解码关闭 → `"no"`
- 若支持直接 MediaCodec（非 Vulkan 或构建支持 MediaCodec-Vulkan）→ `"mediacodec,mediacodec-copy,no"`
- 否则 → `"mediacodec-copy,no"`

在 [`MPVView.initOptions()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L197) 中还强制设置了 `hwdec-codecs=all`，以及 `vd-lavc-dr=auto`、`vd-lavc-queue=no`（见 [`MPVView.kt:241-242`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L241-L242)）。

### 2.4 MPV 配置文件预设

预设定义在 [`PlayerEnums.MPVProfile`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlayerEnums.kt#L113) 中，对应 mpv 内建的 profile 名称：

- `Fast` → `fast`
- `Default` → `default`
- `High Quality` → `high-quality`
- `GPU HQ` → `gpu-hq`
- `Low Latency` → `low-latency`
- `SW Fast` → `sw-fast`

默认值为 `fast`（见 [`DecoderPreferences.kt:21`](app/src/main/java/app/gyrolet/mpvrx/preferences/DecoderPreferences.kt#L21)），在 `initOptions()` 时通过 `PlaybackSession.setOptionString("profile", profile)` 应用。

### 2.5 Surface 帧率匹配

在 [`MPVView.applyFrameRate()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L418) 中，当 Android API ≥ 30 时，若获取到有效的容器帧率（`container-fps`），会调用 `Surface.setFrameRate()` 以 `FRAME_RATE_COMPATIBILITY_FIXED_SOURCE` 模式将 Surface 帧率与视频帧率对齐，减少 judder。

### 3.4 Anime4K 超分

#### 3.4.1 架构概览

Anime4K 实现分为两层：

- **管理层**：[`Anime4KManager`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L19) — 负责 shader 文件的初始化、优化、路径组装。
- **运行时层**：[`Anime4KPlayback.kt`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt) — 负责热保护、运行时降级、shader 链应用。

#### 3.4.2 Shader 初始化与优化

[`Anime4KManager.initialize()`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L94) 将 assets 中的 GLSL shader 复制到应用内部存储 (`filesDir/shaders/anime4k`)，并在复制过程中执行两项关键优化（见 [`Anime4KManager.kt:201-249`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L201-L249)）：

1. **FP16/mediump 优化**：为移动 GPU 注入精度限定符。默认使用 `mediump float`，但包含 FSR（`FsrEasu`/`FsrRcas`）或位操作（`floatBitsToUint` 等）的 pass 保持 `highp`。同时显式重写每行变量声明的精度限定符，因为部分 Adreno 驱动会忽略默认精度头（见 [`Anime4KManager.kt:181-199`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L181-L199)）。
2. **C.R.E.L.U. 纹理采样优化**：将 `go_0`/`go_1` 宏（3×3 卷积核中的重复纹理采样）替换为预取的局部变量，减少纹理读取次数（见 [`Anime4KManager.kt:304-382`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L304-L382)）。

#### 3.4.3 模式与质量

Anime4K 支持 8 种模式（见 [`Anime4KManager.kt:36-66`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L36-L66)）和 3 种质量等级：

**模式**：`OFF`、`A`、`B`、`C`、`A_PLUS`、`B_PLUS`、`C_PLUS`、`ARTCNN`

**质量**：`FAST`（后缀 `S`）、`BALANCED`（后缀 `M`）、`HIGH`（后缀 `L`）

各模式的 shader 链组装逻辑在 [`getShaderFiles()`](app/src/main/java/app/gyrolet/mpvrx/domain/anime4k/Anime4KManager.kt#L430) 中：

- 所有模式均以 `Anime4K_Clamp_Highlights.glsl` 开头（防止 ringing）。
- 模式 A：`Restore_CNN → Upscale_CNN_x2 → AutoDownscalePre_x2 → Upscale_CNN_x2`
- 模式 B：`Restore_CNN_Soft → Upscale_CNN_x2 → AutoDownscalePre_x2 → Upscale_CNN_x2`
- 模式 C：`Upscale_Denoise_CNN_x2 → AutoDownscalePre_x2 → Upscale_CNN_x2`
- 模式 A+：`Restore → Upscale → AutoDownscalePre → Restore → Upscale`
- 模式 B+：`Restore_Soft → Upscale → AutoDownscalePre → Restore_Soft → Upscale`
- 模式 C+：`Upscale_Denoise → AutoDownscalePre → Restore → Upscale`
- 模式 ARTCNN：使用 `Ani4Kv2_ArtCNN_C4F32_i2_CMP.glsl`

可选后处理：
- 去模糊（Deblur）：`Anime4K_Deblur_DoG.glsl`
- 暗化（Darken）：`Anime4K_Darken_Fast.glsl` 或 `Anime4K_Darken_HQ.glsl`
- 细化（Thin）：`Anime4K_Thin_Fast.glsl` 或 `Anime4K_Thin_HQ.glsl`

#### 3.4.4 运行时热保护与降级

[`selectRuntimeStableAnime4K()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt#L47) 在应用 shader 前执行两层保护：

1. **静态热保护**：若视频分辨率 ≥ 4K 且未启用 `anime4kIn4k`，直接关闭 Anime4K（见 [`Anime4KPlayback.kt:33-38`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt#L33-L38)）。
2. ** proactive 热保护**：通过 `ThermalMonitor.getHeadroom()` 检测热余量。若 `headroom < 0.40`， preemptively 降级到 Mode C + FAST（见 [`Anime4KPlayback.kt:63-76`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt#L63-L76)）。
3. **运行时压力保护**：检测掉帧计数（`drop-frame-count ≥ 15`、`vo-delayed-frame-count ≥ 25`、`mistimed-frame-count ≥ 40` 或 `vo-delayed-frame-average-ms ≥ 12.0`），满足任一阈值即降级到 C/Fast（见 [`Anime4KPlayback.kt:86-100`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt#L86-L100)）。

应用 shader 时，[`withPreservedVideoGeometry()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/anime4k/Anime4KPlayback.kt#L144) 会捕获并恢复视频几何属性（`video-zoom`、`video-pan-x/y`、`brightness`、`contrast` 等共 14 项），防止 shader 切换导致画面缩放/平移重置。

### 3.5 自动裁切黑边

自动裁切功能由 `PlayerPreferences.autoCropBlackBars`（键 `auto_crop_black_bars`，默认 `false`）控制。该偏好通过 UI 触发 mpv 的 `crop` 属性调整，源码中未找到独立的自动检测算法实现，实际行为依赖 mpv 原生能力或用户手动触发。

## 四、HDR 支持

### 4.1 HDR 屏幕输出模式

HDR 输出模式定义在 [`HdrScreenMode`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L28) 中：

| 模式 | 说明 | 关联的 HdrToysProfile |
|------|------|----------------------|
| `OFF` | 恢复 mpv 默认自动 SDR/HDR 处理 | 无 |
| `BT_2100_PQ` | HDR10 hdr-toys 管线 | `BT_2100_PQ` |
| `BT_2100_HLG` | HLG hdr-toys 管线 | `BT_2100_HLG` |
| `BT_2020` | BT.2020 hdr-toys 色域管线 | `BT_2020` |
| `LINEAR` | mpv 原生 gpu-next HDR 路径，不使用 hdr-toys shader | 无 |

可选模式列表为 `BT_2100_PQ`、`BT_2100_HLG`、`BT_2020`、`LINEAR`（见 [`HdrScreenOutput.kt:65`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L65)）。默认启用模式为 `BT_2020`（见 [`HdrScreenOutput.kt:68`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L68)）。

### 4.2 HDR 设置应用机制

HDR 相关设置由 `hdrScreenOutputSettings()` 函数统一生成（见 [`HdrScreenOutput.kt:91`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L91)），确保每种模式的设置列表完整且幂等。受控的 mpv 属性共 9 项：

- `target-colorspace-hint`
- `target-colorspace-hint-mode`
- `target-prim`
- `target-trc`
- `target-peak`
- `inverse-tone-mapping`
- `hdr-compute-peak`
- `hdr-reference-white`
- `tone-mapping-visualize`
- `glsl-shader-opts`

**`LINEAR` 模式**使用 mpv 原生 HDR 渲染，设置 `target-colorspace-hint=yes`，并可通过 `boostSdrToHdr` 启用 `inverse-tone-mapping=yes` 将 SDR 内容提升到 HDR 范围（见 [`HdrScreenOutput.kt:160-173`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L160-L173)）。

**hdr-toys 模式**（PQ/HLG/BT.2020）设置 `target-colorspace-hint=no`，避免 gpu-next 在 shader 管线上再协商一次 HDR 输出变换，同时通过 `glsl-shader-opts` 传递 profile 专用的 shader 选项（见 [`HdrScreenOutput.kt:146-158`](app/src/main/java/app/gyrolet/mpvrx/ui/player/HdrScreenOutput.kt#L146-L158)）。

### 4.3 HdrToysManager 与 Shader 管线

[`HdrToysManager`](app/src/main/java/app/gyrolet/mpvrx/domain/hdr/HdrToysManager.kt) 负责将 assets 中的 hdr-toys GLSL shader 复制到 `filesDir/shaders/hdr-toys`，并通过 `MpvShaderRuntime` 命令追加/移除 shader。

各 profile 的 shader 链定义在 [`HdrToysProfile`](app/src/main/java/app/gyrolet/mpvrx/domain/hdr/HdrToysProfile.kt) 中：

- **BT_2100_PQ**：`clip_both → pq_inv → astra (tone-mapping) → bottosson (gamut-mapping) → bt1886`
- **BT_2100_HLG**：`clip_both → hlg_inv → astra → bottosson → bt1886`
- **BT_2020**：`bt1886_inv → bottosson → bt1886`
- **LINEAR**：`clip_black → clip_alpha → astra → bottosson → bt1886`

### 4.4 YUV420P 选项

[`DecoderPreferences.useYUV420P`](app/src/main/java/app/gyrolet/mpvrx/preferences/DecoderPreferences.kt#L31) 控制是否强制使用 YUV420P。启用时，在 `initOptions()` 中通过 `PlaybackSession.setOptionString("vf", "format=yuv420p")` 注入视频滤镜（见 [`MPVView.kt:244-246`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L244-L246)）。

### 4.5 HDR 可用性判定

`LINEAR` 模式仅在 `gpu-next` + Vulkan 同时启用时才可用（见 [`MPVView.kt:208-220`](app/src/main/java/app/gyrolet/mpvrx/ui/player/MPVView.kt#L208-L220)）。若不满足条件，自动回退到 `HdrScreenMode.defaultEnabledMode`（即 `BT_2020`）。

## 五、截图功能

### 5.2 截图质量设置

截图设置封装在 [`ScreenshotSettings`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L45) 中，由 `PlayerPreferences` 持久化：

- `screenshotFormat` — 格式（默认 `PNG`）
- `screenshotTemplate` — 文件名模板（默认 `mpv_snapshot_%Y%m%d_%H%M%S`）
- `screenshotQuality` — JPEG/WebP 质量（默认 `90`，范围 1~100）
- `screenshotPngCompression` — PNG 压缩级别（默认 `7`，范围 0~9）
- `screenshotWebpLossless` — WebP 无损模式（默认 `false`）

这些值在截图前通过 [`applyMpvScreenshotOptions()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L102) 同步到 mpv 的对应选项（`screenshot-format`、`screenshot-template`、`screenshot-jpeg-quality`、`screenshot-webp-quality`、`screenshot-png-compression`、`screenshot-webp-lossless`）。

### 5.3 截图流程

[`ScreenshotSaver.save()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L73) 的执行流程：

1. 同步 mpv 截图选项。
2. 通过 [`ScreenshotTemplate.buildFileName()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L250) 生成文件名。模板变量包括：
   - `%f` — 视频文件名
   - `%F` — 视频文件名（无扩展名）
   - `%p` — 播放位置（HH:MM:SS）
   - `%P` — 播放位置（HH:MM:SS.mmm）
   - `%Y/%m/%d/%H/%M/%S` — 时间戳
   - `%wH/%wM/%wS/%wT` — 播放位置的墙钟时间分量
3. **原生捕获**：调用 mpv 的 `screenshot-to-file` 命令，直接输出目标格式到临时文件（`cacheDir/mpvrx_snapshot_native.*`），等待 250ms 后检查文件（见 [`captureNative()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L111)）。
4. **Android 回退**：若原生捕获失败且格式非 PNG，先以 PNG 格式原生截图，再通过 Android `BitmapFactory` 解码并编码为目标格式（见 [`captureWithAndroidFallback()`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L123)）。WebP 无损模式在 Android R+ 使用 `Bitmap.CompressFormat.WEBP_LOSSLESS`。
5. **保存到相册**：
   - Android Q+：通过 `MediaStore.Images.Media` 插入到 `Pictures/mpvSnaps/`，使用 `IS_PENDING` 标记保证事务性写入。
   - Android Q 以下：直接复制到外部存储的 `Pictures/mpvSnaps/`，并通过 `MediaScannerConnection.scanFile()` 刷新媒体库。

### 5.4 包含字幕选项

`PlayerPreferences.includeSubtitlesInSnapshot`（默认 `false`）控制截图时是否包含当前渲染的字幕。传递给 mpv 的 `screenshot-to-file` 命令的第三个参数为 `"subtitles"` 或 `"video"`（见 [`ScreenshotSaver.kt:118`](app/src/main/java/app/gyrolet/mpvrx/ui/player/screenshot/ScreenshotSaver.kt#L118)）。

## 六、性能与监控

### 6.1 性能追踪（PlaybackPerformanceTrace）

[`PlaybackPerformanceTrace`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackPerformanceTrace.kt#L27) 是一个轻量级的播放性能打点工具，同时支持：

- **Perfetto / Android Systrace**：通过 `Trace.beginSection()` / `Trace.endSection()` 在所有构建中发射 trace slice（无开销除非开启 tracing）。
- **Logcat 里程碑**：仅在 `DEBUG` 构建中输出人类可读的日志（见 [`PlaybackPerformanceTrace.kt:39-41`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackPerformanceTrace.kt#L39-L41)）。

核心 API：
- `mark(name, detail?)` — 瞬时事件
- `begin(name)` / `end(name)` — 区间事件

自动追踪的 mpv 事件（见 [`PlaybackPerformanceTrace.kt:90-95`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlaybackPerformanceTrace.kt#L90-L95)）：
- `MPV_EVENT_START_FILE`
- `MPV_EVENT_FILE_LOADED`
- `MPV_EVENT_PLAYBACK_RESTART`
- `MPV_EVENT_END_FILE`

在 App.kt 的 Activity 生命周期回调中还插入了大量打点：
- `PLAYER_ACTIVITY_STARTED`、`PLAYER_ACTIVITY_STOPPED`
- `PLAYER_ACTIVITY_CREATE_START`、`PLAYER_ACTIVITY_CREATE_END`
- `PLAYER_ACTIVITY_RESUMED`、`PLAYER_FIRST_FRAME`
- `ON_PAUSE`、`ON_STOP`、`ON_DESTROY`

PlaybackSession 内部也在关键路径插入了打点：
- `MEDIA_PREPARATION_START/END` — URI 解析耗时
- `LOADFILE_SENT` — 加载命令发出
- `MPV_STOP_SENT` — 停止命令发出
- `WAIT_FOR_STOP_START/END` — 等待停止完成
- `WAIT_FOR_STOP_SUPERSEDED` — 停止被新请求取代
- `CLOSE_AUDIO_SILENCE` — 关闭时静音

### 6.2 热监控（ThermalMonitor）

[`ThermalMonitor`](app/src/main/java/app/gyrolet/mpvrx/ui/player/ThermalMonitor.kt#L29) 封装了 Android `PowerManager.getThermalHeadroom()` API（API 30+），以 10 秒为周期采样设备热余量（返回值范围 `[0, 1]`）：

- `1.0` — 设备凉爽，可全力运行
- `0.0` — 设备已达热极限，应降低负载

低于 API 30 的设备默认返回 `1.0f`（见 [`ThermalMonitor.kt:47-56`](app/src/main/java/app/gyrolet/mpvrx/ui/player/ThermalMonitor.kt#L47-L56)）。

**热余量到 Ambient Shader 采样预算的映射**（见 [`ThermalMonitor.kt:75-84`](app/src/main/java/app/gyrolet/mpvrx/ui/player/ThermalMonitor.kt#L75-L84)）：

| 热余量 | 严重程度 | 最大采样预算 |
|--------|---------|-------------|
| ≥ 0.80 | 无 | 不限制 |
| 0.60 ~ 0.80 | 轻微 | 12 |
| 0.40 ~ 0.60 | 中等 | 8 |
| < 0.40 | 严重 | 4 (Eco) |

**Anime4K 热节流**：当 `headroom < 0.40` 时，`shouldThrottleAnime4K()` 返回 `true`，触发 Anime4K 降级或关闭（见 [`ThermalMonitor.kt:93`](app/src/main/java/app/gyrolet/mpvrx/ui/player/ThermalMonitor.kt#L93)）。

在 [`PlayerViewModel`](app/src/main/java/app/gyrolet/mpvrx/ui/player/PlayerViewModel.kt#L1945) 中，每 10 秒在活跃播放期间采样一次热余量，当热余量变化超过 0.08 时，使 Ambient shader 缓存失效，以便在下次更新时应用新的采样预算上限。

### 6.3 空闲核心回收

在 [`App.kt`](app/src/main/java/app/gyrolet/mpvrx/App.kt#L266) 中，`startIdleMpvCoreReaper()` 启动了一个协程，持续观察 `PlaybackSession.state`：

当同时满足以下条件时，启动 3 分钟（`IDLE_MPV_CORE_GRACE_MS = 180_000`）的优雅期：
- `phase == PlaybackPhase.IDLE`
- `currentItem == null`
- `!surfaceAttached`
- `PlaybackSession.isInitialized`

优雅期结束后再次检查状态，若仍完全空闲，则调用 `PlaybackSession.destroy()` 销毁 libmpv 核心，释放原生解码器/渲染器资源（见 [`App.kt:284-286`](app/src/main/java/app/gyrolet/mpvrx/App.kt#L284-L286)）。

该机制使用 `collectLatest` 实现自取消：任何新的加载、Surface 绑定、后台会话或其他状态变化都会在销毁执行前中止计时器。

### 6.4 诊断信息中的渲染上下文

在播放器自定义统计页面的诊断信息中，渲染上下文通过以下 mpv 属性实时获取（见 [`PlayerControls.kt:2322-2325`](app/src/main/java/app/gyrolet/mpvrx/ui/player/controls/PlayerControls.kt#L2322-L2325)）：

- `hwdec-current` — 当前活跃硬件解码器
- `gpu-api` — GPU API
- `vo` — 视频输出驱动

解码效率文本的生成逻辑：
- `hwdec-current == "no"` → "Low (Software Decoding, CPU-heavy)"
- 包含 `"copy"` → "Moderate (Hardware-copy, GPU texture overhead)"
- 否则 → "High (Hardware Direct, $gpuApi backend)"

HDR 源检测逻辑（见 [`PlayerControls.kt:2346-2366`](app/src/main/java/app/gyrolet/mpvrx/ui/player/controls/PlayerControls.kt#L2346-L2366)）：
- `video-params/gamma == "pq"` 或 `"hlg"`
- 或 `video-params/primaries == "bt.2020"` 且 `video-params/sig-peak > 1.0`
