# 数据库架构与迁移史

> 本文档基于 `database/` 目录、`di/DatabaseModule.kt` 及 Room Schema JSON 分析得出。

## 1. 数据库概览

| 属性 | 值 |
|------|-----|
| 数据库类 | `MpvRxDatabase`（`RoomDatabase` 子类） |
| 数据库文件名 | `mpvrx.db` |
| 当前 Schema 版本 | **21** |
| 实体数量 | **12 个** |
| Journal 模式 | `WRITE_AHEAD_LOGGING` |
| Schema 导出 | `exportSchema = true`（已导出 19/20/21 三个版本） |

### 1.1 实体清单

| # | 实体类 | 表名 | 用途 |

| 1 | `PlaybackStateEntity` | `PlaybackStateEntity` | 播放进度、轨道选择、缩放等状态 |

### 3.2 各迁移详情

#### MIGRATION_1_2（v1.0.0 → v1.1.0）— 最重大的迁移

**性质**： squashed migration（合并迁移），一次性完成 6 个新表创建和 1 个表重构。

**变更清单**：
1. **PlaybackStateEntity 重构**：
   - 删除 `secondarySid`、`secondarySubDelay`
   - 添加 `videoZoom`
   - 通过 `CREATE TABLE ..._new` + `INSERT SELECT` + `DROP` + `RENAME` 完成
2. **删除** `ExternalSubtitleEntity` 表
3. **新建** `video_metadata_cache` 表（8 个字段）
4. **新建** `network_connections` 表（11 个字段，网络播放基础）
5. **新建** `PlaylistEntity` 表（4 个字段）
6. **新建** `PlaylistItemEntity` 表（7 个字段 + 外键约束 + 索引）
7. **RecentlyPlayedEntity 扩展**：添加 `videoTitle`、`duration`、`fileSize`、`width`、`height`、`playlistId`

#### MIGRATION_2_3（v2 → v3）

- `PlaybackStateEntity` 添加 `externalSubtitles`（TEXT，默认 `''`）
- `video_metadata_cache` 添加 `subtitleCodec`（TEXT，默认 `''`）

#### MIGRATION_3_4（v3 → v4）

- `PlaylistEntity` 添加 `m3uSourceUrl`（TEXT，默认 NULL）
- `PlaylistEntity` 添加 `isM3uPlaylist`（INTEGER，默认 0）

#### MIGRATION_4_5（v4 → v5）

- `PlaybackStateEntity` 添加 `secondarySid`（INTEGER，默认 -1）

#### MIGRATION_5_6（v5 → v6）— 修复型迁移

**问题**：`MIGRATION_2_3` 添加的 `subtitleCodec` 可能在某些数据库中缺失。

**策略**：运行时 `PRAGMA table_info` 检测已存在列，条件性添加：
- `subtitleCodec`（如不存在）
- `hasEmbeddedSubtitles`（INTEGER，默认 0）

#### MIGRATION_6_7（v6 → v7）

- `network_connections` 添加 `useHttps`（INTEGER，默认 0）
- **意义**：WebDAV 连接可显式控制 HTTPS/HTTP，而非从 URL 推断

#### MIGRATION_7_8（v7 → v8）

- `PlaybackStateEntity` 添加 `hasBeenWatched`（INTEGER，默认 0）

#### MIGRATION_8_9（v8 → v9）— 大型修复型迁移

**背景**：部分用户的数据库声称是 v6+，但实际仍保留 v1 的 `secondarySubDelay` 列而非 `externalSubtitles`。

**策略**：
1. `PRAGMA table_info(PlaybackStateEntity)` 检测实际列
2. 若存在 `secondarySubDelay` 或缺少 `externalSubtitles`/`hasBeenWatched`：
   - 重建 `PlaybackStateEntity_new` 表（含完整正确 schema）
   - 使用 `COALESCE` 处理缺失列的默认值
   - 数据迁移后 `DROP` + `RENAME`
3. `PlaylistItemEntity` 条件性添加 7 个 M3U 元数据列
4. `PlaylistEntity` 条件性添加 `userAgent`
5. 新建 `index_PlaylistItemEntity_isFavorite` 索引

#### MIGRATION_9_10（v9 → v10）

- 新建 `directory_scan_index` 表（11 个字段，复合主键 `scanKey` + `path`）
- 新建 2 个索引：`scanKey+rootPath`、`scanKey+isNoMediaRoot`

#### MIGRATION_10_11（v10 → v11）

- 新建 `secure_media` 表（7 个字段）
- 新建唯一索引 `index_secure_media_secureFilePath`

#### MIGRATION_11_12（v11 → v12）

- `PlaylistEntity` 条件性添加 `isAudio`（INTEGER，默认 0）

#### MIGRATION_12_13（v12 → v13）

- 新建 `network_stream_entries` 表（8 个字段）
- 新建索引：`entryType+updatedAt`
- 新建唯一索引：`infoHash+fileIndex`

#### MIGRATION_13_14（v13 → v14）

- `network_stream_entries` 添加 6 个媒体元数据列：`posterUrl`、`backdropUrl`、`groupTitle`、`overview`、`releaseYear`、`mediaType`

#### MIGRATION_14_15（v14 → v15）

- 新建 `jellyfin_servers` 表（6 个字段）

#### MIGRATION_15_16（v15 → v16）

- 新建 `index_RecentlyPlayedEntity_filePath`
- 新建 `index_RecentlyPlayedEntity_timestamp`

#### MIGRATION_16_17（v16 → v17）

- 新建 `download_items` 表（20 个字段）
- 新建 2 个索引：`systemDownloadId`、`jellyfinItemId`

#### MIGRATION_17_18（v17 → v18）

- `download_items` 添加 `stagingPath`（TEXT，可为 NULL）

#### MIGRATION_18_19（v18 → v19）

- `PlaylistEntity` 添加 Xtream 相关 4 个字段：`isXtreamPlaylist`、`xtreamAccountKey`、`xtreamServerUrl`、`xtreamUsername`、`xtreamEncryptedPassword`
- 新建唯一索引 `index_PlaylistEntity_xtreamAccountKey`
- 新建索引 `index_PlaylistEntity_xtreamServerUrl_xtreamUsername`

#### MIGRATION_19_20（v19 → v20）— 修复型迁移

- 新建 `navidrome_servers` 表（8 个字段）
- **防御性 ALTER**：`token` 和 `authMode` 列通过 `try/catch` 包裹，防止重复添加报错

#### MIGRATION_20_21（v20 → v21）— 重复型迁移

- 与 MIGRATION_19_20 几乎完全相同
- **原因**：v20 的迁移可能未在某些设备上正确执行，v21 再次执行以确保 `navidrome_servers` 表存在

#### MIGRATION_19_21（v19 → v21）— 跳级迁移

- 直接从 v19 跳到 v21，内容与 MIGRATION_19_20/20_21 一致
- **目的**：覆盖从 v19 直接升级的用户，跳过有问题的 v20

### 3.3 迁移策略总结

| 策略 | 使用次数 | 典型场景 |
|------|---------|---------|
| `ALTER TABLE ADD COLUMN` | 15+ | 简单列添加 |
| `CREATE TABLE ..._new` + `INSERT SELECT` + `DROP` + `RENAME` | 2 | 表结构重构（MIGRATION_1_2、MIGRATION_8_9） |
| `PRAGMA table_info` 条件检测 | 3 | 修复型迁移（MIGRATION_5_6、MIGRATION_8_9、MIGRATION_11_12） |
| `try/catch` 包裹 ALTER | 2 | 防御重复执行（MIGRATION_19_20、MIGRATION_20_21） |
